# C++
## 约束不匹配报错
### 代码
```cpp
#include<vector>
#include <list>
#include <format>
#include<iostream>
using namespace std;
template <typename T>
    requires std::random_access_iterator<typename T::iterator>
void printc(const T& c) {
    for (auto e : c) {
        cout << format("{} ", e);
    }
    cout << '\n';
    cout << format("element 0: {}\n", c[0]);
}

int main() {
    list<int> c{1, 2, 3, 4, 5};
    vector<int> v{1, 2, 3, 4, 5};
    printc(c);
    printc(v);
}
```

### 分析步骤
mingw 的报错由几个部分组成：
- 错误类型与报错文件、行号（Error/Warning Header），终端中会用高亮标注位置
![[Pasted image 20250805235325.png]]
这一部分格式为 
```cpp
<文件路径>:<行号>:<列号>: <错误级别（error/warning/note）>: <描述信息>`
具体出现错误代码位置
```
其中 `error` / `warning`: 报告种类；`error` 会终止编译，`note` 信息 - 提供“为什么错误发生”的辅助信息，一个 error 或者 warring 一般会跟着几个 note 信息描述。
- Constraint 满足路径与推理过程（Constraint satisfaction failure trace）
错误发生时，编译器会递归查找错误位置的依赖，直到到达最底层。本段代码报错编译器会在层层模板概念中递归“查找到底哪个子约束失败”。

### 收获
报错日志中的关键词（常见标志词）及其含义

| 关键词                                                                 | 类型                     | 含义                                        |
| ------------------------------------------------------------------- | ---------------------- | ----------------------------------------- |
| `error:`                                                            | 要修复的编译失败               | 某些致命结构错误，编译器无法继续编译                        |
| `warning:`                                                          | 可忽略（但不推荐）              | 某些语法/用法不推荐，但能运行                           |
| `note:`                                                             | 帮助信息                   | 辅助解释错误为何发生                                |
| `candidate:`                                                        | 模板推导相关                 | 编译器尝试调用某个函数模板，但推导失败                       |
| `template argument deduction/substitution failed`                   | 模板推导失败                 | 某个模板函数匹配了形参名字，但约束不成立或者无法推导出类型             |
| `constraints not satisfied`                                         | concept 没通过            | 用 `requires` 约束的模板函数最后一个要求失败了             |
| `nested requirement failed`                                         | 概念依赖树中的某一个下级概念失败       | 用于说明某个大 `requires` 是因为嵌套的小 concept 失败才不成立 |
| `requires`                                                          | 内联 constraint 语法       | 表明你需要某个类型具有某种操作或类型特性                      |
| `failed to satisfy` / `does not satisfy` / `requires` 似的 concept 信息 | 说明某个类型在通过 concept 时失败了 |                                           |
| `instantiated from` / `required from here`                          | 你知道模板是从哪一层推导出来的        | 帮你回溯 template 出错路径                        |
