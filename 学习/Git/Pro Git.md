# 版本控制系统

集中式（CVCS）将所有用户连接到一台服务器，管理员权限高自主性好，容易服务器单点故障
分布式（DVCS）客户端保存整个代码仓库镜像和完整提交记录
Git 工作原理是记录每个文件每次更新之间的差异而不是整个文件
Git 中所有的数据在存储前都计算校验和，然后以校验和来引用。并通过 SHA-1 散列值计算比较
一般情况下只能向 git 中添加数据而不能删除

# 使用 git

使用 `git config --list` 显示的配置文件中如果有重复的会默认使用最后一次出现的设置
使用 `$ git config --global core. Editor emacs（编辑器地址）` 更改默认编辑器
使用 `git config <key>` 检查某一项配置
`gir help config` 获取命令手册
工作目录下的每一个文件都不外乎这两种状态：已跟踪或未跟踪。
## 常用操作

| 操作                           | 说明                  | 备注                                           |
| ---------------------------- | ------------------- | -------------------------------------------- |
| `gir clone <website> <name>` | 克隆远程仓库到本地并命名        | 初次克隆某个仓库的时候，工作目录中的所有文件都属于已跟踪文件，并处于未修改状态      |
| `git add`                    | 跟踪新文件或者把已跟踪文件添加到暂存区 | 外部修改暂存区中的文件 git 会创建一个新文件放在工作区中设为未提交，需要重新 add |
| `git status -s(short)`       | 输出简短状态信息            |                                              |
**简短输出内容说明：**
$ git status -s
 M README       # 修改过一次
MM Rakefile      # 修改，暂存之后又做修改
A  lib/git. Rb       # 新添加到暂存区
M  lib/simplegit. Rb    # 已修改已暂存
?? LICENSE. Txt    # 未跟踪

**创建忽略文件：**
```
$ cat .gitignore
*.[oa]
*~
```
第一行告诉 Git 忽略所有以 .o 或 .a 结尾的文件。一般这类对象文件和存档文件都是编译过程中出现的。第二行告诉 Git 忽略所有名字以波浪符（~）结尾的文件

**格式规范**
- 所有空行或者以 # 开头的行都会被 Git 忽略。**用来写注释**
- 可以使用标准的 glob 模式匹配，它会递归地应用在整个工作区中。
- 匹配模式可以以（/）开头防止递归。
- 匹配模式可以以（/）结尾指定目录。
- 要忽略指定模式以外的文件或目录，可以在模式前加上叹号（!）取反。
**支持使用正则表达式**
```git
# 忽略所有的 .a 文件
*.a

# 但跟踪所有的 lib.a，即便你在前面忽略了 .a 文件
!lib.a

# 只忽略当前目录下的 TODO 文件，而不忽略 subdir/TODO
/TODO

# 忽略任何目录下名为 build 的文件夹
build/

# 忽略 doc/notes.txt，但不忽略 doc/server/arch.txt
doc/*.txt

# 忽略 doc/ 目录及其所有子目录下的 .pdf 文件
doc/**/*.pdf
```
[各种语言建议忽略项目](https://github.com/github/gitignore)
根目录中的. gitignore 递归应用整个仓库，子目录中之应用到所在目录
