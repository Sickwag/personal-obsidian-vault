**§1.1 算法**
1. **算法的定义**：是指解题方案的准确而完整的描述。（算法不等于程序，程序的设计不可能优于算法的设计）
1. **算法的基本特征**：可行性、确定性、有穷性、足够的情报。
1. **算法的基本要素**：
    1. 对数据对象的运算和操作：

> 算术运算、逻辑运算、关系运算、数据传输。
1. 算法的控制结构：

> a.算法中各操作之间的执行顺序；
>
> b.描述算法的工具通常有传统流程图、N-S结构化流程图、算法描述语言等；
>
> c.一个算法一般可以用顺序、选择（分支）、循环（重复）三种基本结构组合而成。
1. **算法的时间和空间复杂度**：
    1. 时间复杂度：是指执行算法所需要的计算工作量，可以用算法所执行的**基本**运算次数度量。（是执行代码的次数）
    2. 空间复杂度：是指执行算法所需要的内存空间。包括算法程序、输入的初始数据以及**算法执行过程中**需要的额外空间。
    3. 算法的时间复杂度和算法的空间复杂度相互独立。

1. **存储结构**：又称为数据的物理结构，_是数据的逻辑结构在计算机存储空间中__==存放方式==_

c.两者的存储空间大小
线性表的存储分为顺序存储和链式存储。在顺序存储中，所有元素所占的存储空间是连续的。而在链式存储的方式中，将存储空间的每一个存储结点分为两部分，一部分用于存储数据元素的值，称为数据域；另一部分用于存储下一个元素的存储序号，称为指针域。所以线性表的链式存储方式比顺序存储方式的存储空间要大一些。

一个数组中可以划分出多个部分作为栈的存储空间吗？
为什么假设一个长度为50的数组（编号0~49）中可以设定栈的底端指针需要从49号开始而不从0号开始？
是的，一个数组可以被划分为多个部分，每个部分都可以作为一个独立的栈。这种方法通常被称为**多栈单数组**。在这种情况下，数组中每个部分都有一个栈顶指针，用于跟踪该部分的栈顶元素。
至于为什么栈的底端指针需要从49号开始而不从0号开始，这主要取决于栈的**增长方向**。在大多数现代计算机系统中，栈是向下增长的，也就是说，新的元素被推入栈顶，栈顶指针向下移动。因此，如果我们在数组中实现这样的栈，我们会从数组的末尾（在这种情况下是49号）开始，然后向下（向0号）增长。这样做的一个好处是，它可以使得栈的实现与大多数现代计算机硬件的实现保持一致。
但，这并不是唯一的方式。栈也可以向上增长，即从数组的开始（0号）向数组的末尾（49号）增长。这完全取决于你的具体需求和设计决策。在某些情况下，向上增长的栈可能更适合你的应用。
这是一个简单的例子，展示了如何在一个数组中实现两个栈：
**Python**
`class TwoStacks: def __init__(self, n): # constructor self.size = n self.arr = [None] * n self.top1 = -1 self.top2 = self.size # Method to push an element x to stack1 def push1(self, x): if self.top1 < self.top2 - 1: self.top1 = self.top1 + 1 self.arr[self.top1] = x else: print("Stack Overflow ") exit(1) # Method to push an element x to stack2 def push2(self, x): if self.top1 < self.top2 - 1: self.top2 = self.top2 - 1 self.arr[self.top2] = x else: print("Stack Overflow ") exit(1)`

**循环队列**：是讲队列存储空间的最后一个位置绕道第一个位置，形成逻辑上的环状空间

> rear＞front：s=rear-front
>
> rear＜front：s=容量+rear-front
>
> rear=front：s=1或者s=0

    [判断一个序列是否是堆，可以按照以下步骤进行](https://zhuanlan.zhihu.com/p/262952475)[3](https://blog.csdn.net/u011240877/article/details/47706923)[4](https://bing.com/search?q=%E5%A6%82%E4%BD%95%E5%88%A4%E6%96%AD%E4%B8%80%E4%B8%AA%E5%BA%8F%E5%88%97%E6%98%AF%E4%B8%8D%E6%98%AF%E5%A0%86)：

    1. 将序列看作一棵完全二叉树。
    2. 从最后一个非叶子节点开始，从右到左依次检查每个节点是否满足堆的性质。
    3. 如果所有节点都满足堆的性质，则序列是堆，否则不是堆。

    这里的“堆的性质”指的是：

    - 对于最大堆，每个节点的值都大于或等于其子节点的值。
    - 对于最小堆，每个节点的值都小于或等于其子节点的值。

    也就是说，每一个堆其中元素要么从大到小排列，要么从小到大，堆中每一个元素都是节点，不过注意，每一个堆的都是一个完全二叉树，阅读方法：

    **`heap = [9, 5, 6, 4, 3, 2]`**

    这个序列可以被视为一个最大堆，其中每个元素都是一个节点。在这个堆中，父节点的值总是大于或等于其子节点的值。

    - `**9**` 是根节点，它的子节点是 `**5**` 和 `**6**`。
    - `**5**` 是 `**9**` 的左子节点，它的子节点是 `**4**` 和 `**3**`。
    - `**6**` 是 `**9**` 的右子节点，它的子节点是 `**2**`。
    - `**4**`、`**3**` 和 `**2**` 是叶子节点，它们没有子节点。

    循环队列属于队列的特例和栈同属于线性结构。
    在顺序队列中，由于数组空间不够而产生的溢出叫
    **真溢出**；

**有序表的概念：**
[有序表是一种特殊的线性表，其中所有元素都按照递增或递减的顺序排列。有序表只描述元素之间的逻辑关系，因此有序表既可以顺序存储也可以链式存储](https://blog.csdn.net/wq6ylg08/article/details/103426582)[1](https://blog.csdn.net/wq6ylg08/article/details/103426582)。
[例如，数组](https://blog.csdn.net/wq6ylg08/article/details/103426582) [`int array[3] = [1,2,3];`](https://blog.csdn.net/wq6ylg08/article/details/103426582) [是顺序存储结构的有序表。因它是数组，所以是顺序存储结构；因数据元素](https://blog.csdn.net/wq6ylg08/article/details/103426582) [`[1,2,3]`](https://blog.csdn.net/wq6ylg08/article/details/103426582) [是从小到大排列，所以是有序表。而单链表](https://blog.csdn.net/wq6ylg08/article/details/103426582) [`1->2->3`](https://blog.csdn.net/wq6ylg08/article/details/103426582) [则是链式存储结构的有序表](https://blog.csdn.net/wq6ylg08/article/details/103426582)[1](https://blog.csdn.net/wq6ylg08/article/details/103426582)。
[需要注意的是，有序表与顺序表、链表不是相互独立的，而是内容互相交错的。我们不能把他们相提并论](https://blog.csdn.net/wq6ylg08/article/details/103426582)[1](https://blog.csdn.net/wq6ylg08/article/details/103426582)[。顺序表和链表是根据线性表的存储结构（顺序或链式）来划分概念的，而有序表是根据线性表的数据元素的数值大小来划分概念](https://blog.csdn.net/wq6ylg08/article/details/103426582)[1](https://blog.csdn.net/wq6ylg08/article/details/103426582)。因此，有序表可以是顺序表，也可以是链表，关键在于元素是否按照某种顺序排列。

# **第三章 软件工程基础**
**§3.1软件工程基本概念**
1. **软件**：是由程序、数据及其相关文档构成的集合。
2. **软件的分类**：
    - 系统软件：操作系统、编译程序、汇编程序、网络软件、==数据库管理系统==；
    - 应用软件：事务处理软件、工程与科学计算软件、实时处理软件、人工智能软件；
    - 支撑软件（工具软件）：需求分析工具、编译工具软件、测试工具软件、维护工具软件、驱动软件。
3. **软件危机**：需求增长、开发难控、质量难保、难以维护、提高成本、生产率低。
4. **软件工程**：
    - 定义：应用于计算机软件的定义、开发和维护的一整套方法、工具、文档、实践标准和工序。
    - 其目的是==提高软件生产率、提高软件质量、降低软件成本。==
    - 其核心思想是把软件当作一个工程产品来处理。
5. **软件工程三要素**：
    - 方法：是完成软件工程项目的技术手段；
    - 工具：支持软件的开发、管理和文档生成；
    - 过程：支持软件发开的各环节的控制和管理。
6. **软件生命周期**：
    - 定义：将软件产品产品能够提出、实现、使用维护到停止使用退役的过程称为软件生命周期。
    - 分为软件定义、软件开发及软件运行维护3个时期。维护是持续时间最长，花费代价最大的一个时期。
    - 软件工程学的一个目的就是提高软件的可维护性，降低维护代价。
7. **3个时期共有8个阶段**：

    - 软件定义：问题定义可行性研究、需求分析；
    - 软件开发：概要设计、详细设计、实现、测试；
    - 软件运行维护：使用、维护。
    - **需求分析**：（★）
    - 确定系统的逻辑模型。参加人员有用户、项目负责人和系统分析员。
    - 其工作：需求获取、需求分析、编写需求规格说明书、需求评审。
    - 产生文档：为需求规格说明书。
    - 需求规格说明书的作用：
        - a.便于用户、开发人员进行理解交流；

            b.反映用户问题的结构，可以作为软件开发工作的继承和依据；

            c.作为确认测试和验收的依据。


    1. **需求规格说明书**（SRS）：需求分析阶段产生的主要文档是“软件需求规格说明书”。

> 特点：
- 正确性：体现待开发系统的真是要求；
- 无歧义性：对每个需求只有一种解释；
- 完整性：包括全部有意义的需求；
- 可验证性：每个需求都是可验证的；
- 一致性：各个需求的描述不矛盾；
- 可理解性：需求说明书必须简明易懂；
- 可修改性：结构风格在改变时，是易于实现的；
- 可追踪性：每个需求的来源和流向是清晰的。

**§3.4软件测试**
1. **软件测试**：
2. 软件测试的目的是发现程序中错误。
3. 软件测试的准则：

> a.所有测试都应追溯到用户需求；
>
> b.在测试之前制定测试计划，并严格执行；
>
> c.充分注意测试中群集现象；
>
> d.避免由程序的编写者测试自己的程序；
>
> e.不可能进行穷举测试；
>
> f.妥善保存测试分析报告，为维护提供方便。
1. **静态测试和动态测试**：
2. 静态测试：不实际运行软件，通过人发挥思维优势发现程序的错误。
3. 动态测试：基于计算机的测试，是为了发现错误而执行程序的过程。
4. **白盒测试和黑盒测试**：
5. 白盒测试：把测试对象看作一个打开的盒子，利用程序内部的逻辑结构，对程序所有逻辑路径进行测试。（针对程序的内部逻辑结构）

> a.逻辑覆盖测试；
>
> b.基本路径测试。
1. 黑盒测试：完全不考虑程序内部的逻辑结构，只检查程序是否能接收输入数据而产生正确的输出信息。（针对程序的外部功能）

> a.等价类划分法；
>
> b.边界值分析法；
>
> c.错误推测法。
1. **软件测试步骤**：（顺序不可换）
2. 单元测试：是对软件设计的最小单位——模块进行测试，目的是发现各模块内部的错误。
3. 集成测试：是把模块按照设计要求组装起来的同时进行测试，目的是发现与接口有关的错误。
4. 确认测试：是验证软件功能和性能是否满足各种要求，以及软件配置是否完全、正确。
5. 系统测试：是将软件作为一个元素，与计算机系统其他元素组合在一起，进行集成测试。
**§3.5程序的调试**
1. **程序调试**：
2. 对程序进行了成功的测试之后将进入程序调试，通常称为Debug（排错），主要在开发阶段进行。
3. 程序调试的主要任务是诊断和改正程序的错误。
4. 基本步骤：

> a.错误定位；
>
> b．修改设计和代码，以排除错误；
>
> c.进行回归测试，防止引进新的错误。
1. 软件调试方法：强行排除法、回溯法、原因排除法。

**§6.1计算机病毒的特征和分类**
1. **计算机病毒的含义**：人为编写的一段程序代码或是指令集合，能够通过复制不断感染其他程序、文件等。
2. **病毒**：
3. 本质是一段程序代码；
4. 普通程序通常有独立的程序文件，病毒程序寄生在其他文件上；
5. 特性：

> a.寄生性：寄生在可执行程序中，享有该程序的一切权利。
>
> b.传染性：病毒可以自己扩散到其他文件；
>
> c.破坏性：破坏系统功能、删除重要文件；
>
> d.传播途径：互联网、U盘；
>
> e.潜伏性：病毒程序往往不会马上发作；
>
> f.隐蔽性：有些病毒即使发作，你也注意不到它的存在。
1. 防治方法：安装杀毒软件（及时更新和升级）。

1. **网络的本质**：
