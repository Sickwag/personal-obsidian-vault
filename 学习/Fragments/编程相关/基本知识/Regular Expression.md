# 基础知识
正则表达式用 `/` 括起，`/` 后可以跟一些修饰符
## 语法结构

1. **普通字符**
   - 这是最基本的字符，如字母、数字、汉字等，它们在正则表达式中直接表示其自身。
2. **特殊字符（或元字符）**
   - 这些字符在正则表达式中有特殊含义，例如：`.`、`*`、`?`、`+`、`^`、`$`、`()`、`[]`、`{}`、`|` 等。
   - 例如，`.` 通常表示匹配**除换行符之外**的任意单个字符。
3. **字符类（Character Class）**
   - 用方括号 `[]` 表示，匹配方括号内的任意一个字符。例如，`[abc]` 匹配 `a`、`b` 或 `c` 中任意一个字符。
   - 可以使用连字符 `-` 表示范围，如 `[a-z]` 表示匹配任意小写字母。
1. **否定字符类（Negated Character Class）**
   - 在字符类前加上 `^` 符号，表示匹配不在方括号内的任意字符。例如，`[^abc]` 匹配除了 `a`、`b`、`c` 之外的任意字符。
2. **量词（Quantifier）**
   - 用于指定前面的字符或字符类可以出现的次数。常见的量词包括：`*`（零次或多次）、`+`（一次或多次）、`?`（零次或一次）、`{n}`（恰好 n 次）、`{n,}`（至少 n 次）、`{n,m}`（n 到 m 次）。
   - 例如，`a+` 匹配一个或多个连续的 `a` 字符。
3. **锚点（Anchor）**
   - 用于指定匹配的位置。常见的锚点有：`^`（匹配行的开始）、`$`（匹配行的结束）、`\b`（匹配单词边界）、`\B`（匹配非单词边界）。锚点的定位条件（也就是后面跟的字符）**不会被捕获**，只作为筛选条件使用
4. **分组（Grouping）**
   - 使用圆括号 `()` 来创建子表达式，可以对子表达式进行分组、捕获或应用量词。例如，`(abc)*` 匹配零次或多次出现的 `abc` 字符串。
5. **选择（Alternation）**
   - 使用竖线 `|` 表示“或”操作，匹配左边或右边的表达式。例如，`abc|def` 匹配 `abc` 或 `def`。
6. **转义字符（Escape Character）**
   - 使用反斜杠 `\` 来转义特殊字符，使其表示字面意义。例如，`\.` 表示匹配点字符 `.`。
7. **前瞻和后顾（Lookahead and Lookbehind）**
   - 用于声明一个必须存在但不包括在匹配结果中断言。例如，`(?=abc)` 表示后面跟着 `abc` 的位置，`(?!abc)` 表示后面不跟着 `abc` 的位置。

## 优先级
从高到低
- **转义符号：** `\` 是用于转义其他特殊字符的转义符号。它具有最高的优先级。
    示例：`\d`、`\.` 等，其中 `\d` 匹配数字，`\.` 匹配点号。
- **括号：** 圆括号 `()` 用于创建子表达式，具有高于其他运算符的优先级。
    示例：`(abc)+` 匹配 "abc" 一次或多次。
- **量词：** 量词指定前面的元素可以重复的次数。
    示例：`a*` 匹配零个或多个 "a"。
- **字符类：** 字符类使用方括号 `[]` 表示，用于匹配括号内的任意字符。
    示例：`[aeiou]` 匹配任何一个元音字母。
- **断言：** 断言是用于检查字符串中特定位置的条件的元素。
    示例：`^` 表示行的开头，`$` 表示行的结尾。
- **连接：** 连接在没有其他运算符的情况下表示字符之间的简单连接。
    示例：`abc` 匹配 "abc"。
- **管道：** 管道符号 `|` 表示"或"关系，用于在多个模式之间选择一个。
    示例：`cat|dog` 匹配 "cat" 或 "dog"。

### 修饰符
正则表达式的修饰符（也称为标志或模式修饰符）用于指定额外的匹配策略，它们位于正则表达式之外，格式如下：`/pattern/flags`。
1. **i (ignore case) - 不区分大小写**
   - 使匹配不区分大小写，即搜索时不区分大小写。例如，`/abc/i` 可以匹配 `abc`、`aBC`、`Abc`
2. **g (global) - 全局匹配**
   - 查找所有匹配项，而不是在找到第一个匹配后停止。例如，`/a/g` 会匹配字符串中所有的 `a` 字符。
3. **m (multi-line) - 多行匹配**
   - 使边界字符 `^` 和 `$` 匹配每一行的开头和结尾，而不仅仅是整个字符串的开头和结尾。例如，`/^abc/gm` 会匹配多行文本每行开头的 `abc`。在 vim 或 vscode 中默认使用 m 匹配多行
4. **s (dotAll) - 特殊字符圆点中包含换行符**
   - 默认情况下，`.` 特殊字符不匹配换行符 `\n`，加上 `s` 修饰符后，`.` 可以匹配包括换行符在内的任何字符。例如，`/b./s` 可以匹配 `b` 后跟任何字符，包括换行符。
5. **u (unicode) - Unicode 模式**
   - 使正则表达式以 Unicode 模式运行，允许在正则表达式中使用 Unicode 字符。例如，`/\p{L}/u` 可以匹配任何 Unicode 字母字符。
6. **y (粘性匹配) - 粘性搜索**
   - 从目标字符串的 `lastIndex` 属性指定的位置开始匹配，如果未找到匹配，则返回 `null`。例如，`/a/y` 会从字符串的 `lastIndex` 位置开始查找 `a`。
7. **x (忽略空白) - 忽略模式中空白**
   - 允许在正则表达式中添加空白和注释，这些空白和注释在执行时会被忽略。例如，`/a   #匹配a\nb/x` 中空白和注释在匹配时不会被考虑。
8. **a (仅从 ASCII) - 仅从 ASCII 字符集匹配**
   - 限制匹配仅限于 ASCII 字符集。例如，`/\w/` 在启用 `a` 标志时只匹配 ASCII 字母数字字符。
9. **D (行结束符) - 限制行结束符匹配**
   - 如果使用 `$` 限制结尾字符，则不允许结尾有换行符。例如，`/a$/D` 不会匹配字符串末尾的 `a`，如果字符串以换行符结束。
10. **e (evaluate) - 将匹配结果作为代码执行**
   - 与 `preg_replace_callback()` 函数一起使用时，允许将匹配结果当作 PHP 代码执行。例如，`/(\d+)/e` 可以将匹配到的数字当作 PHP 代码执行。

## 常用结构
### 位置和边界匹配
- `.` 表示任意一个字符
- `[]` 中间的字符集被单独对待，表示方括号中任意一个字符
- `[]` 中可以使用 `-` 表示范围, 字母按照字母表顺序，数字从小到大，区分大小写
![Pasted image 20240928201004.png](Pasted%20image%2020240928201004.png)
![Pasted image 20240928201013.png](Pasted%20image%2020240928201013.png)
- 每一个 `-` 部分都是独立的，`[^a-z]` ，`-` 的优先级高于 `^`，不用连接符连接的作为一个单词被识别，所以 `[^a-zA-Z]` 表示所有除了字母以外的符号
- 方括号中填写的字符**都是字面意思**，不需要转义
- `^` 表示在**方括号内**后面一个单位取反，在**方括号外**表示每一行的开头
- 不用任何字符连接的单词会被组成为一个单位
	![Pasted image 20240928201912.png](Pasted%20image%2020240928201912.png)
	表示匹配 at + 除了所有字母和 1~3 的所有字符
- `.$` 表示每一个 `.` 结尾的行，但这也会匹配到以一个字符结尾的段落，因 `.` 表示除了换行符之外任意一个字符，可以通过 `\.$` 转义，使 `.` 只包含*字面意思*
- `//` 反斜线中间的内容表示需要匹配的字符，`/some/g` 会匹配文章中所有 some 四个字母连一起的字符串，
- `\b` 表示边界，`/\bsome/` 表示匹配以 some 开头的**单词**位置，在单词中间就不会，同理 `/some\b/` 匹配 some 结尾单词，可用 `\B` 取反，表示不在边界
### 量词
-  `*` 前一个字符的任意次数
- `?` 前一个字符的 0 次或 1 次
- `{}` 指定次数
- `{3,5}` 指定 3~5 次，`{3,}` 至少三次
	注意：正则表达式的贪婪匹配原则是指在进行匹配时，正则表达式引擎会尽可能多地匹配字符，直到满足整个表达式的要求。它会从目标字符串的开始处尽可能多地“**吃掉**”字符，直到遇到第一个不满足模式的情况为止，然后回溯到一个满足整个模式的点。
	![3个以上t即可，但更多t也满足，默认使用多的](Pasted%20image%2020240929185112.png)
	相对应的，通过在 \*、+ 、{} 或 ? 限定符之后放置 ?，该表达式从"贪婪"表达式转换为"非贪婪"表达式或者最小匹配。
### 分组
- 通过 `()` 可以创建分组，注意不是方括号，方括号表示**选择**，表示括号中任意一个
- 也可以使用 `|` 来分组，表示**或**，但 `|` 只会作用域两端的一个单位，`/P|pattern/` 是不能匹配大小写首字母的 pattern 的，pattern 是一个单位整体不可分，也可以理解为无连接符优先级高于 `|`

### 替换
- 替换是在分组基础之上建立的，`$` 表示一个分组，用 `()` 创建的分组从 1 开始编号，如 `/(\d{4})[-/._]?(\d{1,2})[-/._]?(\d{1,2})/g` 分成 3 组，`$` 表示一个分组。
-  `(?:) ` 表示不将这个分组作为**非捕获分组**，替换栏中就原分组失效
- 创建分组后引擎自动编号，查找栏中使用 `\数字` 引用相应的分组，替换栏中使用 `$`

### 前瞻和后顾
#### 正向前瞻
作用：匹配满足条件的某个字符串前面或者后面的字符（串），**匹配某个位置的文本，但不包括在匹配结果中。**
语法：`(?=pattern)` 一般需要匹配的文本放在分组中
如[选取所有单词](#选取所有单词)

#### 负向前瞻
作用与前瞻相反，匹配满足条件的文本后面的字符串
在[选取所有单词](#选取所有单词)中，可以优化 reg 表达式为 `/\w+(?!\d)/g`，将后顾匹配条件为**不是数字**即可匹配所有单词

#### 正向后顾
作用：用于检查某个位置前面是否跟随特定的模式，同样不包括这个模式在匹配结果中。即检查以某种字符作为开头的字符串中除了这个开头剩下的后面的部分
语法：`(?<=pattern)`

`/d+` 表示匹配多次出现的数字，`(?<=\$)/d+` 表示以 `$` 开头的多次出现的数字
![Pasted image 20240929201928.png](Pasted%20image%2020240929201928.png)

#### 负向后顾
与正向后顾相反
`(?<!\$)/d+` 表示匹配所有不以 `$` 开头的多次出现的数字字符串
![Pasted image 20240929202121.png](Pasted%20image%2020240929202121.png)

#### 总结
- 前瞻和后顾结构中固定分为捕获部分（没有 `()` 包围）和非捕获部分（用 `()` 包围）
- 非捕获部分使用非捕获符 `?` 和前瞻后顾标记符标记非捕获模式，后跟需要匹配的字段
- `?: `、 `?=` 和 `?!` 是非捕获元
- 前瞻后顾是正则表达式中零宽断言

|语法|作用|名称|
|---|---|---|
|`(?=exp)`|指定后缀|零宽度正预测先行断言  <br>zero-width positive lookahead assertion|
|`(?<=exp)`|指定前缀|零宽度正回顾后发断言  <br>zero-width positive lookbehind assertion|
|`(?!exp)`|指定后缀_不能是_|零宽度负预测先行断言  <br>zero-width negative lookahead assertion|
|`(?<!exp)`|指定前缀_不能是_|零宽度负回顾后发断言  <br>zero-width negative lookbehind assertion|

### obsidian 标题批量调整
`"^(#+)\s(.*)$"->"#$1 $2"`
将所有标题的层级提升一级，可以根据需要调整, 如需要提升 2 级，则使用 `"^(#+)\s(.*)$"->"##$1 $2"`
如果需要将所有标题降低一级，较为麻烦，需要一层一层替换，**从低到高**
`"^(#{2})\s (.*)$"->"# $2"`，所有二级标题替换为一级标题
`"^(#{3})\s (.*)$"->"## $2"`，所有三级标题替换为二级标题
以此类推
