这是一个理论模型，它将网络通信的工作划分为七个层次，每一层都为其上一层提供服务，并调用下一层的服务。

### OSI 七层模型详解

| **第 1 层** | **物理层**<br/>(Physical Layer) | **在物理介质上透明地传输原始的比特流（bit stream）**。它定义了设备的电气、机械、程序和功能规范。<br/>- **定义物理特性**：接口和介质的物理特性（如线缆、接头的形状、针脚数量）。<br/>- **定义电气特性**：比特流的电压大小、编码方式（如 NRZ、曼彻斯特编码）。<br/>- **定义功能特性**：每条线路的功能（数据线、控制线、地线）。<br/>- **定义规程特性**：比特流传输的工作流程和时序。<br/>- **传输原始比特**：发送方发送 1/0，接收方识别 1/0。 | **IEEE 802.3** (以太网物理层标准)<br/>**IEEE 802.11** (Wi-Fi 物理层标准)<br/>**RS-232, V.35** (串行接口标准)<br/>**DSL** (数字用户线路)<br/>**SONET/SDH** (光同步网络)<br/>**蓝牙、Zigbee** 的物理层 | **比特**<br/>(Bit) | **集线器**、**中继器**、**调制解调器**、**网卡** |

### 数据封装过程（发送方）
当一个用户发送数据（如一封电子邮件）时，数据会从**应用层**开始，逐层向下传递。每一层都会为数据添加一个**头部**（和尾部），这个过程叫做**封装**。

1.  **应用层**：原始数据 + **应用层头** = **报文**
2.  **表示层**：报文 + **表示层头** = **报文**
3.  **会话层**：报文 + **会话层头** = **报文**
4.  **传输层**：报文 + **TCP/UDP 头**（含端口号） = **段**
5.  **网络层**：段 + **IP 头**（含 IP 地址） = **包**
6.  **数据链路层**：包 + **帧头**（含 MAC 地址） + **帧尾** = **帧**
7.  **物理层**：将帧转换为 **比特流**，通过物理介质（网线、光纤、无线电波）发送出去。

### 数据解封装过程（接收方）
接收方收到比特流后，执行相反的过程，逐层向上传递，每一层剥掉对应的头部，最终将原始数据交付给目标应用程序。这个过程叫做**解封装**。

### TCP/IP 模型详解

TCP/IP 模型由美国国防部高级研究计划局（DARPA）在 20 世纪 70 年代开发，用于构建 ARPANET（互联网的前身）。它是一个**基于协议**的模型，而不是像 OSI 模型那样严格的理论分层。它通常被划分为**4 层**或**5 层**（有时将网络接口层拆分为数据链路层和物理层）。

| TCP/IP 层数 | 对应 OSI 层 | 层名称 | 功能与作用 | 关键协议 | 数据单位 | 网络设备 |

| **第 4 层** | **应用层**<br/>**表示层**<br/>**会话层** | **应用层**<br/>(Application Layer) | **整合了 OSI 模型中应用层、表示层和会话层的功能**，直接为用户的应用进程提供服务。<br/>- **定义应用间通信的规则**：如 HTTP 用于 Web，SMTP 用于邮件。<br/>- **处理特定的应用细节**：如数据格式转换、加密解密、会话管理都在此层的具体协议中实现。 | **HTTP/HTTPS** (Web)<br/>**FTP, SFTP** (文件传输)<br/>**SMTP, POP 3, IMAP** (电子邮件)<br/>**DNS** (域名解析)<br/>**DHCP** (动态 IP 分配)<br/>**SSH, Telnet** (远程登录)<br/>**SNMP** (网络管理)<br/>**NTP** (时间同步)<br/>**RTP** (实时传输，用于音视频) | **报文**<br/>(Message) | 网关 |

### 数据封装过程（TCP/IP vs OSI）

以一个发送 HTTP 请求的过程为例：

1.  **应用层**：浏览器生成一个**HTTP 请求报文**（`GET /index.html`）。
2.  **传输层**：HTTP 报文交给 TCP。TCP 为其添加一个**TCP 头部**（包含源端口号、目标端口号 80 等），形成**TCP 段**。此举确保了 Web 服务器上的 HTTP 服务能收到这个请求。
3.  **网际层**：TCP 段交给 IP。IP 为其添加一个**IP 头部**（包含源 IP 地址、目标 IP 地址等），形成**IP 数据报**。此举确保了数据能跨越多个网络路由到正确的目标服务器。
4.  **网络接口层**：IP 数据报交给以太网驱动程序。驱动程序将其封装成一个**以太网帧**，添加**帧头**（包含源 MAC 地址、目标 MAC 地址——通常是下一跳路由器的 MAC 地址）和**帧尾**（FCS 校验码）。最后，硬件将帧转换为**比特流**，通过网线发送出去。

**接收方**则执行完全相反的解封装过程。

### TCP/IP 模型 vs OSI 模型：核心区别

| 特性        | **OSI 七层模型**                  | **TCP/IP 四层模型**                                 |
| :-------- | :---------------------------- | :---------------------------------------------- |
| **本质**    | **理论模型** (Conceptual Model)   | **协议模型** (Protocol Model)                       |
| **产生方式**  | 由 ISO 组织先制定标准，后实施。            | 先有协议和实践，后总结成模型。                                 |
| **层数**    | **7 层**，划分清晰，职责分明。            | **4 层**（或 5 层），更简洁实用。                           |
| **设计出发点** | 追求理论的完整性和标准化，希望成为全球通用标准。      | 为了解决实际网络互联问题，强调异构网络的互操作性。                       |
| **关键层**   | **网络层**和**传输层**都是核心。          | **网际层 (IP)** 是**绝对核心**，是“互联网”的基石。               |
| **流行度**   | 主要用于**教学和理论研究**，是理解网络概念的完美工具。 | **实际互联网中广泛使用**的架构，所有互联网设备都遵循它。                  |
| **面向连接**  | 网络层和传输层都支持面向连接和无连接。           | 仅在传输层提供面向连接（TCP）和无连接（UDP）服务，网际层 (IP) 是**无连接**的。 |

### 物理设备功能
集线器->**工作在物理层**，从一个端口收到的数据被转发到所有其他端口，无论与端口相连的系统是否准备好。
中继器->中继器是局域网互连设备，工作于 OSI 体系结构的**物理层**，识别信号后再生信号，将其发送到网络的其他分支上（**信号放大器**）
网桥->数据链路层
交换机->数据链路层，将一个端口接受的数据转发到指定端口中，交换机具备自动寻址和交换的功能，每个端口的带宽相同且共享
1. 集线功能。提供大量可供线缆连接的端口达到部署星状拓扑网络的目的。
2. 中继功能。在转发帧时重新产生不失真的电信号。
3. 桥接功能。在内置的端口上使用相同的转发和过滤逻辑。
4. 隔离冲突域功能。将部署好的局域网分为多个冲突域，而每个冲突域都有自已独立的带宽，以提高交换机整体宽带利用效率。
基本交换原理：
- 转发路径学习。根据收到**数据帧中的源 MAC 地址建立该地址同交换机端口的映射**，写入 MAC 地址表中，下次就可以直接根据 mac 地址直接找到这个 mac 对应的主机在哪一个端口，向这个端口发送消息，**省去建立连接和分配端口过程**
- 数据转发。如果交换机根据数据帧中的目的 MAC 地址在建立 n 好的 MAC 地址表中查询到了，就向对应端口进行转发。
- 数据泛洪。**如果数据帧中的目的 MAC 地址不在 MAC 地址表中，则向所有端口转发**，也就是泛洪。广播帧和组播帧向所有端口（不包括源端口）进行转发。
- 链路地址更新。MAC 地址表会每隔一定时间（如 300 s）更新一次，防止表存储内容过多
