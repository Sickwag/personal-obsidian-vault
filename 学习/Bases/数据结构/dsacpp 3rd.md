### 复杂度测量
#### 复杂度计算
- 时间复杂度
	从保守估计的角度出发，在规模为 n 的所有输入中选择执行时间最长者作为 `T(n)`，并以 `T(n)` 度量该算法的时间复杂度。
- 渐进复杂度
	在大 O 记号的意义下，函数各项正的常系数可以忽略并等同于 1。
	多项式中低次项均可忽略，只需保留最高次项。

	在大Ω几号的意义下，得到的是对算法执行情况的最乐观估计
	这些都是在 n 足够大（处理的数据足够多使函数接近下界，O 则是上界）
	将时间复杂度理解为算法中各条指令的执行时间之和。在图灵机（Turing Machine, TM）和随机存储机（Random Access Machine, RAM）等计算模型中，指令语句均可分解为若干次基本操作，**从而将 T (n) 定义为算法将T(n)定义所执行基本操作的总次数**，即算法所需要的基本操作的次数通过时间变换函数（`T()`）计算得到时间

- 多项式复杂度
多项式时间复杂度被视作一个具有**特殊意义的复杂度级别**。多项式级的运行时间成本，在实际应用中一般被认为是可接受的。某问题若存在**一个复杂度在此范围以内**的算法，则称该问题是可有效求解的或易解的（tractable）
在这个范围中，相对于多项式中最高级的一项以下级数的指数级复杂度，二者之间不超过多项式规模的差异小到可以忽略不计
- 指数复杂度数 `O(2^n)`
[C++ Runoob Tutoral \> 固定次数的 while 循环](C++%20Runoob%20Tutoral.md#固定次数的%20while%20循环)
```cpp
__int64 power2BF_I(int n)
{                    // 幂函数2^n算法（蛮力迭代版），n >= 0
    __int64 pow = 1; // O(1)：累积器刜始化为2^0
    while (0 < n--)  // O(n)：迭代n轮，殏轮都
        pow <<= 1;   // O(1)：将累积器翻倍
    return pow;      // O(1)：迒回累积器
} // O(n) = O(2^r)，r为输入指数n癿比特位数
```
整个算法共需 `O(n)` 时间，一般地，凡运行时间可以表示和度量为 T (n) = O (an) 形式的算法（a > 1），均属于“指数时间复杂度算法”（exponential-time algorithm）。
在问题规模不大时，指数复杂度反而可能在较长一段区间内均低于多项式复杂度

==多项式与指数是无法等量齐观的两个截然不同的量级==，原因是无法确定指数的底数和多项式的底数。通常认为指数复杂度的算法无法应用于实际问题中，
### 递归
**递归基指的是算法存在一个或多个不需要再次递归的实例**，作为递归的末尾判断，避免无限递归
自我调用通常是直接的，即在函数体中包含一条或多条调用自身的语句。
递归也可能以间接的形式出现，即某个方法首先调用其它方法，再辗转通过其它方法的相互调用，最终调用起始的方法自身。
#### 递归的使用
- 线性递归：算法 sum () 每一递归实例对自身的调用至多一次。于是，每一层次上至多只有一个实例，且它们构成一个线性的次序关系。
- 减而治之：递归的目的都是一样的：通过递归不断地将算法规模减小一个常数，避免复杂的分支和嵌套循环
```cpp
int sum_array(int A[],int n){
    if(1>n){
        return 0;
    }else {
        sum_array(A, n - 1) + A[n - 1];
    }
}
```
- 递归的创建、调用和销毁有操作系统完成，一般**不会超过递归函数中计算所需要时间**
- 数组倒置的递归算法
```cpp
void array_reverse(int A[],int begin,int end){
    if(begin <= end){
        swap(A[begin], A[end-1]);
        // cout << A[begin] << endl;

}
```

#### 递归的优化
**前置知识**：
1. 计算机处理所有数据都通过二进制方式，所以向 `powe_func` 中传入参数时，计算机会先把参数**根据数据类型**转换为二进制数，如 `int n = 10` 会被转化为 `00000000 00000000 00000000 00001010`，
2. 对于开平方运算，对于需要开平方的数 n 对于整数类型，**至多**经过 `r = 1 + log2^n` 次循环，n 就会变为 0 结束迭代。开平方算法的循环次数和开平方的算法逻辑有关系，所以对于蛮力迭代的开平方算法，**输入的 n 大小决定运行时间（循环次数）**，传入 n 对应需要 2^r 次循环 `O(n) = O(2^r)`

```cpp
}
```

```cpp
    if (low == high) {
```

- 经连续 ` m = log 2^n` 次递归调用，数组区间的长度从最初的 n 首次缩减至 1，到达第一个递归基。

- 到达区间长度为 `2^k `的任一递归实例之前，已执行的递归调用总是比递归返回多`m-k` 次。

##### 递归求斐波那契数列
- 并非所有问题都适宜于采用分治策略。实际上除了递归，此类算法的计算消耗主要来自
- 子问题划分，即把原问题分解为形式相同、规模更小的**独立的**子问题，比如代码 1.11 中 sum () 算法将待求和数组分为前、后两段。
- 其次是子解答合并，即由递归所得子问题的解，得到原问题的整体解，比如由子数组之和累加得到整个数组之和。
**高效实现上面两个步骤的需要保证子问题的划分标准清晰严密**，保证子问题独立可解，字问题之间不相互调用（这样会导致层级混乱，代码也不易读）
```cpp
// 代码1.12二分递归计算fibonacci数
__int64 fibonacci(int n){
    return (2 > n) ? (__int64)n : fibonacci(n - 1) + fibonacci(n - 2);
}
```
代码计算斐波那契数列的第 n 项数字大小，斐波那契数列的极限增长率 `lim v = F(n+1)/F(n)` =φ, 其中​​ ![Pasted image 20241017124712.png](Pasted%20image%2020241017124712.png) 为黄金增长率，所以最后一个斐波那契数 n 需要经过 n 次递归才可以变为 1 到达 return 递归基，`O (φ^(n+1)) = O (2^n)`，不能用于实际中

##### 解决重复递归的两种方法
1. 制表（tabulation）或记忆 memoization）策略：每遇一个子问题，先查验它是否计算过，通过调阅记录，从而避免重新计算。
```cpp
//代码1.13 通过线性递归计算Fibonacci数
__int64 fibonacci(int n, __int64& previous){
    if( 0 ==n){
        previous = 1;
        return 0;
    }else {
        __int64 prePrevious;
        previous = fibonacci(n - 1, prePrevious);
        return previous + prePrevious;
    }
}

int main()
    __int64 previous;
    __int64 result = fibonacci(5, previous); // 计算 F(5)
    cout << "F(5) = " << result << ", F(4) = " << previous << endl;
    return 0;
}
```
- 这段代码是线性递归的，累计耗时不超过 O (n)，n 次递归同样需要 O (n) 规模的附加空间
---
1. 动态规划（dynamic programming）策略：从递归基出发，自底而上递推地得出各子问题的解，直至最终原问题的解。
```cpp
// 代码1.14基二劢态觃划策略计算Fibonacci数
__int64 fibonacci (int n){
    __int64 f = 0, g = 1;
    while (0<n--){
        g += f; // 将当前的斐波那契数加到下一个斐波那契数上
        f = g - f; // 更新当前斐波那契数为新的下一个斐波那契数减去当前斐波那契数
    }
    return f;
}
```
1. 初始化 `f = 0` 和 `g = 1`。
2. 第一次循环：`n = 4`，`g += f` 变为 `1`，`f = g - f` 变为 `1`。
3. 第二次循环：`n = 3`，`g += f` 变为 `2`，`f = g - f` 变为 `1`。
4. 第三次循环：`n = 2`，`g += f` 变为 `3`，`f = g - f` 变为 `2`。
5. 第四次循环：`n = 1`，`g += f` 变为 `5`，`f = g - f` 变为 `3`。
6. 第五次循环：`n = 0`，循环结束，`f` 的值为 `3`，即斐波那契数列的第 5 项。
- 这种算法根据斐波那契数列原始定义计算，g表示 f 下一个数，f 表示第循环次数的斐波那契数
- 每循环一次便自底向上推断一个数，时间复杂度为 `O(n)`
- 没有使用递归，每循环一次旧值被覆盖，使用空间大小是常量 `O(1)`

### 抽象数据类型
---
**封装：** 将数据项与相关的操作结合为一个整体，并将其从外部的可见性划分为若干级别，从而将数据结构的外部特性与其内部实现相分离，提供一致且标准的对外接口，隐藏内部的实现细节。
**封装数据的结果：** 数据集合及其对应的操作可超脱于具体的程序设计语言、具体的实现方式，即构成所谓的==抽象数据类型（abstract data type, ADT）==。抽象数据类型的理论催生了现代面向对象的程序设计语言，而支持封装也是此类语言的基本特征。

## 向量
根据数据项之间的某种**逻辑次序的复杂程度**，大致可以将各种数据结构划分为三大类
1. 线性结构、
2. 半线性结构
3. 非线性

根据其中数据项的**逻辑次序与其物理存储地址的对应关系**不同，又可进一步地将序列区分为向量（vector）和列表（list）。
- 在向量中，所有数据项的物理存放位置与其逻辑次序完全吻合，此时的逻辑次序也称作秩（rank），其中元素**以秩区分**，这也是为什么 vector 中可以存放不同类型的数据的原因，因元素之间通过秩而不通过同一数据类型所展示的值来区分；
- 而在列表中，逻辑上相邻的数据项在物理上未必相邻，而是采用间接定址的方式通过封装后的位置（position）相互引用。
### 从数组到向量
- 对于任何 `0 <= i < j < n，A[i]` 都是 `A[j]` 的前驱（predecessor），`A[j]` 都是 `A[i]` 的后继（successor）。如果 i 与 j 相差 1，则两者关系式是直接前驱 / 后继（immediate predecessor/successor）
- 采用这种**编号规范**允许直接==直接==访问数组中任何一个元素，==直接==表示可以在常数时间内对这些元素完成**读取，修改**等基本操作。由于容器单位大小已被定义，可以通过**一次乘法运算和一次加法运算**，获得待访问元素的物理地址。 ^dda323
- 若数组 ` A[]` 存放空间的起始地址为 A，（C++中直接使用 A 返回 A 第一个元素物理地址）
- 且每个元素占用 s 个单位的空间，则元素 `A[i]`对应的物理地址为：`A + i * s`，可以用这个等式计算地址的数组叫做**线性数组**
- 以递归调用中递归调用实例作为向量中元素为例，元素的前驱元素数量等于它的秩，由于他是线性的，所以秩的大小反映了这个元素的创建时间。这样通过创建时间（rank）可以定位到相应的实例，反之亦然
- 因向量之间根据秩区分对象，不同对象之间没有定义运算法则没有可比性和计算性。但可以通过重载运算符来排序容器中对象（参考 [C++ Runoob Tutoral \> 自定义比较器](C++%20Runoob%20Tutoral.md#自定义比较器)）
