## 数据结构为何重要
数据结构不只是用于组织数据，它还极大地影响着代码的运行速度。
因数据结构不同，程序的运行速度可能相差多个数量级。
### 1.1 基础数据结构：数组
一般的数据结构都允许**读取，查找，插入，删除**四种用法
为了避开算法速度收到硬件和环境的影响，操作的速度，并不按时间计算，而是按步数计算。

#### 查找
线性查找的方式是最基本，最低效的方法，一个 N 格的数组，其线性查找的最多步数是 N。

#### 插入
**往数组里插入一个新元素的速度，取决于你想把它插入到哪个位置上**
插入新元素的操作分为：移动插入位置后面的所有元素（在这里仅仅对于数组这种线性表而言）+ 写入新的元素，平均花费 `N/2 + 1` 步
#### 删除
数组的删除就是消掉其**某个索引上的数据**
同理，删除数据之后也需要移动删除元素后面的所有元素向前移动一格

### 1.2 集合：一条规则决定性能
是一种不允许元素重复的数据结构。
读取操作完全一致，
在插入操作中，首先逐一检查每一个元素是否和要插入的元素相同，**再检查完所有元素之后插入**
在插入过程中还有移动操作

## 算法为何重要
代码的速度主要来自于数据结构和算法的影响
### 2.1 有序数组
- 有序数组的插入
将需要插入的元素和数组中元素逐一对比，直到第一次发现有元素和需要插入的数字大小的比较结果与之前的比较结果相异时结束比较，进行插入操作（同样的移动后再插入）
**这样插入的方法很慢**，但也使它在查找操作上有优势
### 2.2-2.3 有序数组的查找
线性查找：有序数组的顺序数组具有提前终止查找的功能，`[3,17,75,80,202]` 里查找 `22`，我们可以在查到 `75` 的时候就结束
二分查找：在长度很大的数组需要查找时具有很大的优势

## 大 O 记法
### 3.1 大 O ：数步数
- 若用大 O 记法来描述一种处理一个 N 元素的数组需花 N 步的算法的效率是 O (N)。
- O (1) 意味着一种算法无论面对多大的数据量，其步数总是相同的。就像无论数组有多大，读取元素都只要 1 步。
- 大 O 记法不只是用固定的数字（如 22、440）来表示算法的步数，而是基于要处理的数据量来描述算法所需的步数。或者说，大 O 解答的是这样的问题：**当数据增长时，步数如何变化？**
- O (N) 算法所需的步数等于数据量，意思是当数组增加一个元素时，O (N) 算法就要增加 1 步。而 O (1) 算法无论面对多大的数组，其步数都不变。
### 3.2 常数时间和线性时间
**常数时间**：不管数据量怎样变化，算法的步数都恒定
**线性时间**：算法步骤数和数据量呈线性关系
100 步的算法在效率上不如 1 步的算法，但如果它的步数是恒定的，那么 `O (100) ` 还是比 `O (N)` 更高效

### 3.3-3.4 二分查找的时间复杂度
二分查找的大 O 记法是：`O(logN)`，`O (log N)` 意味着该算法当数据量翻倍时，步数加 1

## 运用大 O 来给代码提速
### 4.1 冒泡排序
如何将一个无序的数字数组整理成升序？
```Python
def bubble_sort(list):
    unsorted_list = len(list)-1
    sorted = False
    while not sorted :
        sorted = True
        for i in range(unsorted_list):
            if list[i] > list[i+1]:
                sorted = False
                list[i],list[i+1] = list[i+1],list[i]
        unsorted_list -= 1

list = [3,7,9,2,8,12,7]
bubble_sort(list)
print(list)
```
用 Python 写起来确实快了很多，print 可以直接接受一个容器，值交换也很方便 `list[i], list[i+1] = list[i+1], list[i]`，这种是 Python 推荐的交换容器中元素的方式

### 4.2-4.4 冒泡排序的效率
以最坏情况估计，N 个元素的 list 需要循环 N 次，一次循环中检查所有相邻元素需要 N-1 次，每循环一次N--
交换共计 ` (N - 1) + (N - 2) + (N - 3) + … + 1 = N*(N-1)/2` 次
循环共计 ` (N - 1) + (N - 2) + (N - 3) + … + 1 = N*(N-1)/2` 次
共计  `N*(N-1)/2 ` 次
所以冒泡排序的时间复杂度是 `O(N^2)`

## 用或不用大 O 来优化代码
如何分辨那些效率貌似一样的算法，从而选出较快的那个。
### 5.1-5.4 选择排序的逻辑和效率
```Python
# 选择排序
def selection_sort(list):
    for i in range(len(list)):# 假设当前索引时列表中最小的索引
        min_index = i
        for j in range(i+1,len(list)):# 检查列表剩余部分是否有更小的元素
            if list[j] < list[min_index]:
                min_index = j
        list[i],list[min_index] = list[min_index],list[i]
    return list

list = [3,7,9,2,8,12,7]
print(selection_sort(list))
```

比较的次数和冒泡排序一样，但交换次数是容器中元素数量-1，即总循环次数-1
因大 O 算法不包含除指数以外的数字，所以选择排序尽管比冒泡排序高效，**但两者 O 是一样的。**
![Pasted image 20241018130220.png](Pasted%20image%2020241018130220.png)
这就是大 O 记法忽略常数的原因。大 O 记法只表明，对于不同分类，存在一临界点，在这一点之后，一类算法会快于另一类，并永远保持下去。至于这个点在哪里，大 O 并不关心。
