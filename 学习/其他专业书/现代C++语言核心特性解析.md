# 新基础类型（C++11 C++20）
## 整数类型 long  long
整数字面量后缀 `LL` & `ULL`，同样，printf 中支持使用 `%lld` 和 `%llu` 来格式化

## 新字符类型 `char16_t` 和 `char32_t`
在 C++11 标准中添加两种新的字符类型 `char16_t` 和 `char32_t`，它们分别用来对应 Unicode 字符集的 UTF-16 和 UTF-32 两种编码方法
### 符符集集和和编编码码方方法法
一个字符集的字符是稳定的。而编码方法是利用数字和字符集建立对应关系的一套方法（Unicode 字符集就有 UTF-8、UTF-16 和 UTF-32 这 3 种编码方法）

对于两者的透彻理解可以参考 ai 对于单个 char 为什么不能存储一个中文字符的回答：

1.  **C++标准本身不规定 `char` 的编码方式**：`char` 只是一个“字节”大小的整数，用来表示一个字符。但它具体对应哪个字符，是由你**编译环境**的“字符集”决定的。
2.  **在几乎所有的现代系统上，默认编码是 ASCII**：ASCII 编码只支持英文字符、数字和符号（0-127），不支持中文。这就是为什么直接用 `char` 保存中文会乱码。
3.  **`char` 可以保存中文**：但这需要你明确地告诉编译器，你要用的是一种支持中文的编码，最常见的就是**UTF-8**。
#### 1. `char` 的本质

在 C++中，`char` 的本质是一个**整数类型**，通常占用 1 个字节（8 位）。它的值范围是-128 到 127（或有符号）或 0 到 255（无符号）。
那么，这个整数如何变成一个“字符”呢？这就要靠**编码**了。
  **编码** 就像一个“密码本”，它规定了数字（字节）和字符（如 'A', '你', '好'）之间的对应关系。因 ASCII 只用了 7 位（0-127），所以一个标准的 `char` 类型可以完美地存储所有 ASCII 字符。
#### 2. 为什么 `char` 不能直接存中文？（ASCII 的局限性）
中文、日文、韩文等非拉丁语系有成千上万个字符，远超 ASCII 127 个字符的限制。因此，需要更复杂的编码方式。
最初人们为中日韩文字符设计了**GBK, Big 5, Shift-JIS**等编码，但这些编码之间互不兼容，造成了很大的混乱。为了解决这个问题，**Unicode**应运而生。
**Unicode**是一个“万国码”，它为世界上几乎所有的字符都分配了一个唯一的数字，这个数字被称为**码点**。

例如：
*   'A' 的码点是 `U+0041`
*   '你' 的码点是 `U+4F60`
*   '好' 的码点是 `U+597D`
#### 3. Unicode 编码的实现方式：UTF-8, UTF-16, UTF-32
Unicode 只是一个标准，它规定每个字符的“码点”，但没有规定如何将这些码点存储在内存或文件中。具体如何存储，由 UTF-8、UTF-16、UTF-32 等**Unicode 转换格式**来实现。
这里我们重点讲与 C++ `char` 关系最密切的 **UTF-8**。

UTF-8 是**目前互联网上最流行、最广泛使用的编码方式**。它的最大特点是：
*   **变长编码**：它可以用 1 到 4 个字节来表示一个字符。
*   **完全兼容 ASCII**：对于 ASCII 字符（0-127），UTF-8 就用 1 个字节表示，且和 ASCII 的编码完全一样。对于非 ASCII 字符（如中文），则用 2 到 4 个字节表示。
**UTF-8 如何存储中文：**
以中文“你”（`U+4F60`）为例：
*   它的 UTF-8 编码是三个字节：`0xE4, 0xBD, 0xA0`
*   这三个字节的十进制值是 `228, 189, 160`

**结论**：如果你想用 `char` 类型保存一个中文字符“你”，你不能用一个 `char`，而是需要**三个连续的 `char`**，分别存这三个字节的值。
#### 4. C++11 如何支持多字节字符（如 UTF-8）的 C++代码？
在 C++11 之前，处理多字节字符（比如中文）非常麻烦。C++11 引入了 `char16_t` 和 `char32_t` 来分别表示 UTF-16 和 UTF-32 编码的字符，并引入了**字符串字面量**来指定编码。
但，对于 UTF-8，我们更常用 `char` 数组或 `std::string`，因它就是字节序列。C++20 甚至将 UTF-8 提升为源代码和字符串字面量的默认编码。
**如何写一段支持中文的 C++代码？**
使用UTF-8 格式保存 `main.cpp`
```cpp
#include <iostream>
#include <string>
#include <clocale> // mark1

int main() {
    std::setlocale(LC_ALL, "zh_CN.UTF-8");  // mark2
    const char* str_chinese = u8"你好, C++!";  // mark3

    std::cout << "使用 char 和 UTF-8 打印: " << str_chinese << std::endl;
    std::cout << "字符串长度: " << std::string(str_chinese).length() << std::endl; // 输出 6，因UTF-8是按字节计算的
}
```
- mark 1：这个头文件用于设置本地化环境，以便控制台正确显示，如果在终端中使用了字符输出编码格式修改命令（如 windows 的 `chcp 65001`）设置了，就可以不用。
- mark 2：配合 mark 1 头文件使用，但在Linux/macOS上可能不需要这行，或者设置不同的值
- mark 3：显示说明这个字符串使用 utf-8 编码
### 总结

| 问题 | 答案 |
| :--- | :--- |
| **`char` 使用的编码方式是什么？** | C++标准不规定，由**编译环境**决定。在现代系统中，默认是**ASCII**。 |
| **`char` 是否支持保存中文？** | **支持，但不是用一个 `char` 保存一个中文字符。** |
| **如何用 `char` 保存中文？** | 使用**UTF-8**编码。一个中文字符通常由**3 个连续的 `char`**（字节）表示。你需要将源文件保存为 UTF-8 格式，并在代码中使用 `u8"..."` 前缀来标记字符串是 UTF-8 编码。 |
| **最佳实践是什么？** | 1. **保存文件为 UTF-8 格式。**<br>2. **在代码中广泛使用 `u8` 字符串字面量。**<br>3. **处理单个字符逻辑时，优先考虑 `char32_t`（`U"..."` 前缀），因它能直接对应 Unicode 码点，逻辑更清晰。**<br>4. **进行网络传输或文件存储时，优先使用 UTF-8 编码的 `char` 序列（`std::string` 或 `char*`）。** |

简单来说，对于现代 C++开发，**请默认使用 UTF-8 编码**，并用 `char` 和 `u8` 前缀来处理包含中文等多语言文本的字符串。
