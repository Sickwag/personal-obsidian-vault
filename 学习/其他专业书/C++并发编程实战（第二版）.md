## 什么是并发
### 并发的方法
并发（concurrency）是两个或多个同时独立进行的活动。单处理器机器通过频繁地 cpu 占用任务切换“实现并发”，多处理器机器通过多个 cpu 同时运行不同任务实现**真并发**
假并发实现是在每次切换任务时必须完成一次上下文切换（context switch），需要
- 操作系统需保存当前任务的 CPU 状态和指令指针
- 判定需要切换到哪个任务，并为之重新加载 CPU 状态
- 将新任务的指令和数据从内存加载到 CPU（双核机每个任务等分之间只有这一个任务，所以等分之间的分隔**比单核机要细**）

### 并发的方式
#### \[前置知识\]进程和线程区别
##### 核心比喻：厨房与厨师
想象一个**餐厅的厨房**。
*   **进程**：就是这个**整个厨房**。
    *   它拥有自己独立的**资源**：厨房空间、厨具（锅、刀、砧板）、食材、水电燃气。
    *   每个厨房（进程）都是独立的。中餐厨房和西餐厨房互不干扰，它们有各自的资源和规则。
    *   操作系统就是这家餐厅的**总经理**。

*   **线程**：就是在厨房里工作的**厨师们**。
    *   他们**共享**这个厨房里的所有资源（空间、厨具、食材）。
    *   厨师们协同工作，共同完成一顿饭（比如一个任务）。一个厨师切菜，另一个厨师炒菜，第三个厨师摆盘。
    *   他们之间沟通非常高效，因为他们就在同一个空间，能看到对方在做什么，能直接拿到对方处理好的半成品。
##### 实际概念
1. 进程 - 独立的“程序世界”

一个进程就是一个**正在执行中的程序**。打开一个软件操作系统就为它创建了一个进程。
*   **资源分配的基本单位**：操作系统以进程为单位，为它分配独立的内存空间（厨房空间）、系统资源（如文件句柄、网络端口）等。
*   **隔离性与稳定性**：每个进程都拥有自己独立的“小世界”（内存空间）。这意味着：
    *   **一个进程崩溃（比如浏览器闪退），通常不会影响其他进程（比如你的音乐播放器还在继续播放）**。就像中餐厨房着火了，西餐厨房还能正常运营。
    *   进程之间的通信比较麻烦和低效（称为 IPC，进程间通信），就像两个厨房的厨师需要通过对讲机或者传菜员来沟通，远不如在同一个厨房里直接说话快。
2. 线程 - 进程内部的“执行流”
线程是**进程中的一个执行单元**，是 CPU 调度和执行的基本单位。一个进程至少有一个线程（主线程），也可以有多个线程。
*   **执行的基本单位**：***CPU 真正执行的是线程中的指令***。我们说一个程序是“多任务”的，实际上是指它内部有多个线程在并发执行。
*   **共享资源**：同一个进程下的所有线程**共享**这个进程的全部资源，特别是内存空间。
    *   **优点**：线程间通信极其高效。因为它们共享内存，一个线程可以直接读写另一个线程的数据。就像厨师 A 切好菜，直接放在砧板上，厨师 B 伸手就能拿走去炒。
    *   **缺点**：**缺乏隔离性**。如果某个线程由于 bug 写乱了共享内存，可能会导致整个进程崩溃（所有线程都“死掉”）。就像一个厨师把厨房的总电闸拉错了，导致整个厨房瘫痪。这也被称为“线程不安全”。
##### 关键区别总结表格

| 特性 | 进程 | 线程 |
| :--- | :--- | :--- |
| **基本定义** | **资源分配的基本单位**，一个独立的程序实例。 | **CPU 调度的基本单位**，进程内部的一个执行流。 |
| **资源开销** | **大**。创建和销毁需要分配/回收独立的内存、资源，开销大，速度慢。 | **小**。创建和销毁只在进程内部，共享资源，开销小，速度快。 |
| **通信方式** | **复杂、低效**。需要**进程间通信（IPC）**，如管道、消息队列、共享内存等。 | **简单、高效**。直接读写**共享的进程内存**即可。 |
| **隔离性** | **强**。一个进程崩溃，一般不影响其他进程。**稳定性高**。 | **弱**。一个线程崩溃，通常会导致整个进程崩溃。**稳定性低**。 |
| **切换成本** | **高**。切换进程需要保存和恢复整个内存空间、寄存器等大量状态。 | **低**。切换线程只需保存和恢复少量寄存器状态，因为内存空间不变。 |
##### 注意
一个应用程序也有可能有有多个进程，这通常用于浏览器等过于复杂的应用中
多个进程可以**真正地并行**运行在不同的CPU核心上，从而最大限度地利用硬件性能
较为复杂的应用中使用多进程将核心功能和组件功能隔离开来，保证安全
#### 多进程并发
将一个应用软件拆分成多个进程同时运行
缺点：
- 由于进程需要有有大量防护措施，所以启动多个进程开销会很大（时间和空间）
- 进程间通信和进程管理**必须通过操作系统**，通信开销会很大
优点：
- 可以通过网络，在不同计算机上运行一个软件的不同进程，提高并发力度
- 进程间严格隔离，非常安全
#### 多线程并发
C++更青睐线程间通信
**进程间通信必须依靠对应平台的 API 实现（需要通过操作系统）**，

#### 并发和并行
两个术语都是指使用可调配的硬件资源同时运行多个任务，但并行更强调性能

- 这个暂停检查的时间必须非常短（否则影响播放）且频繁（否则用户操作丢失）
