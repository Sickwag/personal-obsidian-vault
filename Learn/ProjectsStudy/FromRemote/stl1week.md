# Function：类型擦除的阅读入口
## 这一篇要解决的问题
相同调用签名的普通函数、仿函数、捕获 lambda 可以交给统一接口使用。`Function<Ret(Args...)>` 通过保存具体对象，再借助虚接口转发调用实现这一点。
## 正文
### 精读顺序

| 顺序 | 源码位置 | 要回答的问题 |
| --- | --- | --- |
| 使用现场 | `src/test_Function.cpp:15-33` | `repeattwice` 如何接收三种可调用对象？`auto ff = f` 触发什么操作？ |
| 模板形态 | `include/_Function.hpp:13-26` | 主模板如何拒绝无效签名？偏特化如何提取返回类型与参数包？ |

| 构造入口 | `include/_Function.hpp:67-71` | 如何推导、约束、转换并保存传入对象？ |
| 调用与复制 | `include/_Function.hpp:76-98` | 调用如何返回结果？复制如何得到独立的目标对象？ |

### 构造、调用与复制链
以 `repeattwice([=](int i) { ... })` 为例，调用者创建的闭包对象含有捕获状态。进入接受 `const Function<void(int)>&` 的接口前，隐式构造一个临时 `Function<void(int)>`，该临时对象存活至包含此次调用的完整表达式结束。
构造链：闭包对象 → `Function(_Fn&&)` 推导 `_Fn` → `std::decay_t<_Fn>` 得到存储类型 → 分配 `_FuncImpl<存储类型>` 并构造其 `_M_f` → `_M_base` 以 `unique_ptr<_FuncBase>` 持有该对象。
外层 `Function<void(int)>` 只依赖统一基类接口。具体闭包类型保留在 `_FuncImpl<F>` 的模板实例及其成员 `_M_f` 中；通过 `_M_base` 调用时，运行期虚分派选择对应实现。
调用链：`func(1)` → `Function::operator()` → 检查 `_M_base` → 虚调用 `_M_call` → `_FuncImpl<F>::_M_call` → `std::invoke(_M_f, ...)` → 目标函数返回 → 原路返回给调用者。若 `_M_base` 为空，在进入虚调用前抛出 `std::bad_function_call`。
复制链：`auto ff = f` → `Function(const Function&)` → 虚调用 `_M_clone()` → 新建同类型 `_FuncImpl<F>` → 用旧 `_M_f` 复制构造新目标。两个包装器拥有不同的实现对象；若闭包捕获了引用、指针或共享所有权对象，闭包内部仍可能访问相同外部资源。
销毁链：`Function` 析构 → `_M_base` 析构 → 经 `_FuncBase` 的虚析构销毁实际 `_FuncImpl<F>` → 销毁 `_M_f` 并释放实现对象占用的存储。被引用捕获的外部对象，其生命周期仍由外部负责。
### 方案取舍

| 方案 | 具体类型与状态如何保存 | 调用方式 | 适用边界 |
| --- | --- | --- | --- |
| 函数指针 | 保存入口地址；捕获状态需要额外设计上下文传递 | 通过函数指针间接调用 | 接口简单，单个函数指针无法直接容纳带捕获 lambda |
| 函数模板参数 `F` | 编译期保留具体类型，状态由对象保存 | 对具体类型调用，编译器有机会内联 | 每个 `F` 产生相应实例，接口保持泛型 |
| 本仓库 `Function` | 堆上保存 `_FuncImpl<F>` 与目标对象 | 统一虚接口再调用具体目标 | 接口可固定签名，代价包含分配与虚分派；复制要求目标可复制 |

当前实现通过 `make_unique` 保存目标，没有看到内联缓冲区分支。由源码可以确定该设计使用动态分配与虚接口；调用耗时、优化器是否消除某次分配或分派，需要针对实际编译结果测量。
### 当前源码需要区分的边界
- 构造约束已由 `enable_if_t` 改为 `requires`，附近注释仍使用旧术语。学习以当前表达式为准，后续可单独比较 SFINAE 与约束的候选筛选机制。
- `operator=(const Function&)` 声明返回 `Function&`，函数体缺少 `return *this`。这是源码检查发现的问题；本次示例使用复制构造，尚未实例化并验证复制赋值路径。
- 示例成功执行仅覆盖已触发的路径，无法据此认定所有成员均可正确实例化，或与 `std::function` 完全等价。

## 练习与理解检验
练习目标：区分包装器的独立所有权与闭包内部状态的共享关系。先预测现象，再在明确要求开展代码实验时执行。
1. 构造保存 `[n = 0]() mutable { return ++n; }` 的 `Function<int()> f`，复制为 `g`，依次调用 `f()`、`f()`、`g()`，预测三次返回值并沿 `_M_clone` 解释。
2. 将捕获方式改成对同一外部整数的引用捕获，重新预测结果，并说明两个 `_FuncImpl` 的独立分配为何仍能产生共享状态。
3. 在源码中指出：编译期的具体类型在哪里保留，运行期的统一接口从哪里开始，复制目标对象所需的能力由哪段代码提供。
## 小结
- `Function` 固定调用签名，`_FuncImpl<F>` 保存具体对象，`_FuncBase` 提供统一操作接口。
- 构造保留具体类型，调用通过虚接口转发；复制依靠克隆得到独立的实现对象。
- 包装器独立拥有目标对象，与目标对象内部是否共享资源是两个需要分别追踪的问题。
