# 按 JD 生成针对性面试准备
目标是让候选人拿到"针对这家公司这个岗位"的可直接说出口的材料，而不是把通用自我介绍换成公司名。
**基准是文件里已有的公司条目**：本科在读、找实习/校招的应届生视角，口语、简短、诚实。不要写成资深工程师的技术答辩。
## 读取入口
1. 确认 vault 根目录，读取根 `AGENTS.md`、`.agents/Context.md`、`.agents/Style.md`；用 `.agents/KnowledgeMap.md` 定位面试相关笔记。
2. **完整读** `Chores/JobInterviews/面试准备.md`：`## 具体公司` 里已有公司的写法是语气和结构的唯一基准，`# 通用反问` 是反问去重的基准。
3. 读 `Chores/JobInterviews/简历内容.md` 拿正式简历表述；需要项目细节时读 `Chores/JobInterviews/简历项目问题.md` 交叉核对。
4. 只处理用户本轮明确给出的新公司岗位。已存在但既无 JD、也无内容的旧公司不补写、不改动。
5. 输入不足时先问：JD 原文、公司全称、岗位名、是否实习、工作地。缺 JD 不凭公司名推测岗位。
## 输入与来源边界
- 三份输入：**JD 原文**（用户粘贴或已在文件中）、**本人简历与项目**（只来自仓库文件）、**公司/产品公开资料**（网络）。
- 网络资料只用于公司、产品、客户行业这类外部事实；个人经历、项目指标、技术选型只能来自简历与项目笔记，禁止用检索结果补写个人经历。
- 来源优先级：公司官网（关于/产品/解决方案/加入我们/新闻）> 官方招聘页 > 行业媒体/公众号。招聘网站只用来对照 JD 与真实技术栈。
- 记录可核验来源，写成公司小节下的一行：`公司信息与产品资料：[标题](链接)、[标题](链接)`。
- 区分"公司自述"与"可验证事实"：宣传口径（如"拆图 100% 准确"）不当成技术事实断言。找不到的信息写"待确认"，不编造版本号、人数、客户名、面试流程。
## 检索与核验
1. 检索公司名 + 产品名，弄清四件事即可：**产品是什么**（做什么用的软件）、**技术底座**（什么平台、什么语言、什么数据库）、**客户是谁**（哪些行业）、**团队多大**。
2. 检索"公司名 + 招聘 / 岗位"，把官网或招聘平台的岗位原文与用户 JD 对照：差异以用户 JD 为准，原文能补出隐藏要求（如"具备机械模具背景优先"）。
3. 检索深度到"能回答『你了解我们公司吗』"这一层就够。**不要用查到的架构细节去设计问题或反问**——实习生答不上，面试官也不会用那种方式考实习生。
4. 检索结果冲突时以官网最新发布为准；打不开、需登录、只有摘要的页面降级为待确认。
## 公司画像与岗位画像
- **公司画像**：成立时间、主营产品、技术底座、客户行业、团队规模。用途是让自我介绍里出现"我知道你们在做什么"的一两句具体话。
- **岗位画像**：把 JD 每条要求拆成能力项并标权重——核心（必须答得上）、加分（能展示更好）、门槛（学历/城市/实习时长）。
- **映射**：能力项 → 简历里能指到项目的证据（项目名 + 做了什么 + 用什么做的）→ 缺什么、打算怎么补。
- **落点**：一句"为什么是这家公司这个岗位"，一句"我缺什么、打算怎么补"。缺口写实（如 C# 没写过、模具工艺不懂），比假装全能更能取信。
## 四章节写作规范
### 自我介绍
- **直接套用文件里已有公司条目的模板**，只替换成本公司相关的内容：
```md
面试官好，我是吉林农业大学计算机科学与技术专业的 2027 届本科生，专业成绩排名前 10%。我应聘贵司的<岗位名>，主要方向是<方向>。
我认为我的能力合适主要来自于 N 点
- 第一是<最贴 JD 的能力>，<证据>，<成绩/结果>。
- 第二是<第二能力>，<具体做过什么>，<和贵司业务的关系>。
- 我还在<实习经历>，<做了什么>，这段经历让我<收获>。
- 最后是<数据库/新语言/实习期等收尾项>，<如实说缺什么>，<怎么补>；实习期我可以稳定投入 6 个月以上。
贵司的技术指导我会很珍惜。希望能加入贵司工作。谢谢。
```
- 正文 250~400 字，`N 点` 写 3~5 点，每点一到两句话，能被一口气读完；不写 1 分半长篇，不写"综上所述"。
- 能力点按 JD 权重排序：JD 最看重的那条放第一点。与本公司产品同类的那段项目经历优先。
- 必须有一句如实交代短板（语言没写过、行业不懂、工具没用过），并给出时间预期（如"一个月能改小功能"），这比"学习能力强"有说服力。
### 可能提出的问题
- **只写 4~5 个，必须是实习生/应届生在真实面试里会遇到的问题**：你了解我们公司吗、挑一个项目讲、会不会我们的主力语言、数据库和 SQL 用过哪些、线代/基础课学过没有、实习能投入多久、为什么投我们、以后想做什么方向。
- **禁止架构级拷问**：不要写"三个平台怎么抽象""实体 ID 怎么保证稳定""识别规则库还是模型"这类资深工程师或技术负责人级别的问题，面试实习生不会问，写了也用不上。
- 每题结构固定、简短：`**问题**` + `答题要点：` + 3~4 条要点（每条一句话，说明怎么答、举哪个例子、哪里如实承认）。
- 答题要点要能直接说出来，不要写成知识点讲解；不写"考点/主动给坑/追问预警"这类标签。
- 最多在两三题里带一条"可能追问"，且追问也必须是实习生能接住的（如表很大怎么查快、矩阵求逆会不会）。
### 自身优势
- 4~5 条平实的分点，每条一句话，格式与自我介绍的能力点一致，不重复叙述项目细节。
- 最后一条固定写"不装的部分"：明确列出没写过/没学过/不了解的东西，再给一句补救计划。
- **不用大表格**、不写"差异化在哪"这类总结段，不做量化包装。
### 反问
- **必须是普通实习生问得出口的问题**，5~6 条，平铺成列表（与 `# 通用反问` 的格式一致）：会做哪个语言方向、需要提前学什么、开发流程和有没有人 review、软件卖给哪些行业、能不能去客户现场、表单和进度怎么记录、版本多久发一次、晋升项目经理要几年。
- **禁止向面试官提架构/技术方案级别的反问**（多平台内核、实体 ID 稳定性、识别规则库、AI 落地路线），也禁止质问式、试探公司技术水平的问法。
- 每条反问只写问题本身，不加"目的："注解，不解释为什么问。
- **必须逐条比对 `# 通用反问` 去重**：具体工作、转正名额、试岗期、培养计划、入职团队、考核期待、上班时间、加班、结果时间，这些一个都不写；换角度时也要确保问的是另一件事（如问"开发流程"而不是问"有没有培养计划"）。
## 写入位置与格式
- 位置：`Chores/JobInterviews/面试准备.md` → `## 具体公司` → `## <公司全称>--<岗位>` → `### JD` → 四章节。
- 章节顺序固定为 `### 自我介绍`、`### 可能提出的问题`、`### 自身优势`、`### 反问`；`# 通用反问` 保持在文件末尾且不改动。若用户已删掉其中某个标题，按用户留下的结构写，并在回复里说明。
- 骨架：
```md
## <公司全称>--<岗位名>
公司信息与产品资料：[官网](url)、[产品页](url)
### JD
（用户提供的 JD，逐字保留，不改写不精简）
### 自我介绍
面试官好，我是吉林农业大学计算机科学与技术专业的 2027 届本科生……
我认为我的能力合适主要来自于 4 点
- 第一是……
- 第二是……
- 我还在……
- 最后是……
贵司的技术指导我会很珍惜。希望能加入贵司工作。谢谢。
### 可能提出的问题
**一、你了解我们公司是做什么的吗？**
答题要点：
- ……
- ……
### 自身优势
- ……
- 不装的部分也说清楚：……
### 反问
- ……
- ……
```
- 遵循 `.agents/Style.md`：段落紧凑不留空行、嵌套缩进 4 空格、中英文与数字之间加空格、标题不加序号和 emoji。
- 只追加不改写：用户手写的旧公司段落、通用反问一节一律保留原文。
## 自查清单
- [ ] 自我介绍套的是文件里已有公司条目的模板（"我认为我的能力合适主要来自于 N 点"结构、结尾那句"贵司的技术指导我会很珍惜"），250~400 字
- [ ] 四个章节齐全，`### JD` 原文未被改动
- [ ] 可能提出的问题 4~5 个，全部是实习生会遇到的普通问题，没有架构级拷问
- [ ] 反问 5~6 条，平铺列表、无"目的"注解，与 `# 通用反问` 无重复项
- [ ] 每条能力点都能追到简历里的具体项目或实习动作，没有无法验证的形容词
- [ ] 如实写了短板与补救计划，没有把"学习能力强"当优势
- [ ] 公司事实有来源链接；宣传口径没有当成技术事实
- [ ] 段落紧凑、缩进 4 空格、无 tab 和表格滥用，`git diff --check` 通过
- [ ] 未改动历史公司与通用章节，未运行索引 `update`/`desc`，未提交 Git
## 禁止事项
- 不写资深工程师视角的问题与反问（架构抽象、内核适配策略、算法路线选型）。
- 不写长篇技术论证、不堆术语、不做"考点/追问预警/目的"式结构化包装。
- 不编造项目细节、性能指标、公司内部信息、面试轮次与流程。
- 不复制通用反问，不为凑数写满问题列表。
- 不顺手改动 `面试准备.md` 之外的笔记；要补知识走 `interview-question-merge`。
- 不自动 `git commit`、`git push`，不自动更新索引数据库。
