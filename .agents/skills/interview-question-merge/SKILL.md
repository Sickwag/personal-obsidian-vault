# 面试题合集合并
目标是把零散的面试题变成**可检索、可复习、信息高密度**的章节，而不是把题目和网上的答案原样贴进来。合集已有的结构就是规范：`## 领域` → `### 问题` → `回答话术` / `知识点讲解` / `可能的追问`。
## 读取入口
1. 确认 vault 根目录，读取根 `AGENTS.md`、`.agents/Context.md`、`.agents/Style.md`。
2. 读目标文件 `Chores/JobInterviews/面试题合集.md` 的领域清单与目标章节正文：
```sh
grep -n '^## ' "Chores/JobInterviews/面试题合集.md"
grep -n '^### ' "Chores/JobInterviews/面试题合集.md"
```
3. 大文件分段读：只读目标章节前后各 30~60 行，不整篇塞进上下文；确认相邻章节的主题递进关系，决定插入位置。
4. 查重用 2~3 个关键词，只读工具：
```sh
python3 .obsidian/notes-index/notes_index.py lookup "关键词"
python3 .obsidian/notes-index/notes_index.py lookup '同义词|近义词' --regex
```
索引只覆盖前三层标题且可能过期，候选必须打开正文核对；查不到时用 `rg` 搜正文（章节更深、术语在文中出现的情况都靠 rg 补）。
## 原始题的处理
- 用户贴的题通常是碎片：一句话多问、自带口语答案、错别字、概念混用、重复提问。逐条编号处理，不整段搬运。
- 先判"问的是哪个知识点"，再判"这个问法本身是否成立"。例如"poll 的 ET 和 LT 区别"就不成立——ET 是 epoll 独有，poll 只有水平触发。**不成立的问法要在正文里先纠正，再给正确内容**，并在回复中说明这是 corrected。
- 用户自带的答案只当线索，必须核验：正确则并入话术；过时或错误则写清纠错依据（版本、官方手册、源码行为），旧表述可以保留为"常见误解"但必须标明。
- 同一知识点的相邻小问合并进一个 `###`（如"NULL 占空间吗"与"NULL 和空字符串区别"），不为碎片单独建章节。
## 知识点拆分与归位
1. 拆成原子知识点：机制、关键结构、参数与默认值、边界与失败模式、两种以上方案的对比、代码语义、工程坑。
2. 查重后四选一，结论要在回复里写明：
    - `existing`：已有章节完整覆盖且无新增信息 → 不改文件。
    - `merged`：已有章节可补充 → 在该章节追加段落，或往它的 `> [!Info] 可能的追问` 里加 `> - Q/A` 两行一组。**不新建第二个 callout 块**。
    - `new`：无对应章节但已有领域 → 在该领域内新建 `###`，插到语义相邻处，保持知识递进顺序。
    - `new-domain`：连领域都没有 → 新建 `## <领域>`，放在既有章节的合理位置，不新增顶级目录。
3. 归位速查：索引/存储/事务/SQL → `## 数据库`；缓存与持久化 → `## Redis`；消息中间件 → `## 消息队列`；进程线程协程与调度 → `## 操作系统`；I/O 复用、构建、动态库 → `## Linux 与系统编程`（epoll 协议相关常与 `## 计算机网络` 的 select/epoll 章节互链）；网络协议 → `## 计算机网络`；AI、工具链、研发流程 → `## 项目与学习习惯`；身份认证、架构设计 → `## 系统设计`。
4. 插入位置的决定因素不是"新不新"，而是**读者复习顺序**：索引结构 → 聚簇索引与回表 → 最左前缀与索引下推 → SQL 优化 → 表结构与存储 → 事务。
## 章节内固定结构
````md
### <问题，用疑问句，不加序号>
关联笔记：[[Learn/.../笔记#章节]]        # 目标必须真实存在，没有就整行不写
**回答话术：**
（先结论后依据；2~6 段或列表；口语但精确，能被复述）
***引申知识: ...***，参考[[#相关章节|说明]]，参考[[#相关章节|说明]]   # 可选，互链 ≤ 3 条
**知识点讲解：**
```lang
（代码、命令、结构图或数据流；必须给话术之外的新信息）
```
> [!Info] 可能的追问:
> - Q: ...
> - A: ...
````
- 对比类内容用表格，表格前留一个空行；列表缩进 4 空格；不使用 tab。
- 代码块必须标注语言（`sql`/`cpp`/`text`/`bash`），无法运行的示意要在正文说明。
- 新章节的互链优先指向同文件已有章节 `[[#章节|说明]]`，其次指向 `Learn/` 里的知识笔记。
## 写作与信息增量规范
- 遵循 `.agents/Style.md`：零废话、一句一事实、无"首先/其次/总的来说"、无拟人比喻、无 emoji；中英文与数字之间加一个半角空格；`<头文件>` 必须写成行内代码。
- 每节至少回答"是什么 / 为什么 / 怎么做 / 代价"中的三项，缺的项用一句话点到，不展开废话。
- **表格、代码块、追问必须提供话术之外的新信息**：协议字段、版本差异、默认值、实测命令、失败模式、内部实现。只复述话术的示例一律删掉。
- 版本敏感的事实标版本：`CHECK` 约束 8.0.16 起生效、混合持久化 4.0 起、ICP 5.6 起、`vfork` 语义差异等。
- 数量级与性能结论给可验证依据：`EXPLAIN` 字段、`SHOW SESSION STATUS` 计数、手册章节、可复现命令，而不是"通常更快"。
- 引申不超过 2 层；第 3 层及更深的知识转 `Learn/` 笔记，合集里只留 wikilink。
## 关联笔记校验
- `关联笔记：` 只写真实存在的文件与标题，写入前核对：
```sh
grep -n '^## ' "Learn/Language/DB/MySQL.md"
grep -rn '章节名' Learn/
```
- 标题必须逐字一致，包含全角标点（`？`、`（）`、全角逗号），否则 Obsidian 跳转失败。同名笔记加库内路径消歧。
- 找不到合适目标时宁可不写这一行，也不要指向不存在的章节。
## 验收
- [ ] `git diff --check` 通过（既有 CRLF 用 `git -c core.whitespace=cr-at-eol diff --check`）
- [ ] 新增 `###` 都挂在已有 `##` 下，标题层级不跳级，标题无序号与 emoji
- [ ] 表格前有空行、缩进 4 空格、新增行无 tab
- [ ] 所有 `[[...]]` 目标章节都能在对应文件中找到
- [ ] 只追加或有依据的局部修正，用户既有段落、既有 `Q/A` 未被删除或改写
- [ ] 每条原始题都有 existing/merged/new/corrected/deferred 结论与原因
- [ ] 未运行索引 `update`/`desc`，未 `git commit`、未 `git push`
## 禁止事项
- 不把同一知识点写成两个章节；不为凑数拆章节、不为覆盖而重复已有内容。
- 不编造版本号、默认参数、源码行为；不确定就写"待验证"并记为 deferred。
- 不顺手格式化整篇文件、不批量改既有标题、不重排用户已有章节。
- 不写"面试官问这个问题是想考察……"式的元叙述，也不写自我总结段。
