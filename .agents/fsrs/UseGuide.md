# FSRS Review 使用指南
新版 1.0.0 当前处于临时库验收阶段，正式库旧插件停用、旧数据保留。自动化测试不等于真实 Obsidian 桌面验收。
## 职责与入口
- DSH 每晚 22 点处理 `Learn/Fragments/ReadyToMerge.md`，调用学习资源入库 Skill，整理知识和附件，再根据 Git 增量及本次入库正文生成复习材料。
- 插件只消费已发布文件，显示今日复习、记录真实评分、计算 FSRS 下次到期并提醒更新状态。插件不启动 Agent、不调用模型、不自动提交 Git。
- 时间、保持率及建议题量读取 `.agents/Context.md`。建议预算不阻止继续复习；原始知识笔记保留在原学科目录。
## 临时库验收
源码项目位于旧插件同级的 `obsidian-FSRSScheduler-v2/`；`acceptance-vault/` 是只含固定测试题的验收库，不含本人学习历史。
1. 在 Obsidian 中将 acceptance-vault 作为另一个库打开，允许本地社区插件，确认 FSRS Review 已启用。
2. 打开“今日复习”，确认出现“ET 读取边界”、首次检验计数和更新时间；此时评分次数应为 0。
3. 点击“开始回忆”，确认评分要点默认隐藏。独立尝试后展开要点，按真实表现选择 Again/Hard/Good/Easy。
4. 关闭并重新打开此库，确认真实评分仍在，新题已进入下一次调度。
5. 对其他夹具重新创建验收库，验证“只阅读，不评分”、今天稍后做、暂停与恢复；它们不冒充成功回忆。
6. 在来源变化时，旧题应暂缓；外部材料的实质修订显示待确认，不静默继承掌握记录。
7. 检查窗口焦点恢复、跨日提醒、原文跳转及 Markdown 渲染；这些是自动 DOM 测试无法替代的桌面验收项。
完成后向 Agent 反馈通过项与问题，再决定正式替换。当前安装脚本只接受带验收标记的临时库。
## 正常每日使用
- 本人在 ReadyToMerge 对应日期下粘贴资料链接或明确的本地资料路径，保留日期格式 `## YYYY-MM-DD`。
- DSH 根据入库 Skill 逐条整理，失败保留待办；当天全部完成才标记“已完成整理”。已完成日期新增资源仍会处理。
- 新题通过来源与结构校验后自动显示；首次真实评分才进入学习后的 FSRS 状态。Hard 表示独立答对但困难，看答案后觉得熟悉不能记为 Hard/Good。
- 只阅读、实践完成、跳过和暂停分别处理。缺席不补写失败；回来后按实际作答时间调度。
- 题目有问题可以暂停，随后在外部 Agent 中核对来源并生成修订。
## 更新时间的含义
“最近任务成功”是一次完整处理成功的时间；“实际内容更新”是知识或复习材料发生有效更新的时间。没有新内容的成功检查正常记录为成功，运行状态文件本身不算知识更新。
默认预期上海时区 22 点完成，保留 60 分钟宽限；超过预期后提示检查 DSH。插件退出后不运行，下次打开或焦点恢复时补检查。
## 运行与故障
- 没有新题：可能没有有效知识变化，或材料给出了不出题原因；已有到期题仍正常出现。
- partial：有未完成资源或显式问题，成功游标未推进；已完成部分保留，下次继续。
- 来源已变化：重新 prepare 和生成材料，不编辑已发布包，不沿用旧答案。
- 进程异常退出后发现锁文件：先关闭相关库并确认没有处理任务，再由 Agent 核对锁和未完成发布；不要在仍有写入时删除锁。
- 采用单设备评分。不同设备同时修改同一卡片产生事件分叉时隔离该卡并报告，不猜测合并真实评分。
- Git、Python、Node 缺失时报告缺失项，由本人处理。不要自动安装依赖、更新索引或改 DSH 配置。
