# FSRSScheduler 使用指南
版本：0.2.0。复习工作区默认位于 `.obsidian/customDocument/FSRSScheduler/`，原始笔记保留在 `Learn/` 等原目录，材料归档在 Vault 根目录的 `Chores/reviewDocs/`。
## 每次打开后的流程
1. 启动后至少等待 5 秒，再执行原有 Git 检查与增量扫描。自动化已启用时，后台使用固定的 `gpt-6-luna`、`max` 推理强度准备材料。
2. “今日复习”直接列出 FSRS 到期旧知识、待首次检验或修订的题目、近期章节阅读入口。没有新提交时，已有到期卡片仍然出现。
3. 新题先展示场景、问题、检验价值与预计耗时。点击“确认题目并开始”后独立作答，再展开评分要点并按实际表现评分。
4. “开始复习”与“继续下一题”均不限时长、不受每日新卡数量截断；参考时长只用于估算。大主题可以分多次完成，已完成的阅读与评分会持久保存。
5. “今天跳过”将该题延后约 24 小时，不记答错；“已阅读本章节”仅记录阅读，不冒充独立回忆成功。
## 笔记变化
“笔记变化”按文件名和标题层级列出章节；完整路径放在悬浮提示。“查看章节差异”在 Obsidian 内显示上次已阅读章节版本到当前内容的增删，提供每处变更的行号跳转。“打开章节”在新标签页打开原笔记，保留复习页。
新来源按 Markdown 标题分段，忽略代码围栏中的伪标题，并保留同名章节的顺序。修改同文件其他章节不会使该章节卡片失效。删除、移动、格式调整有单独标记；标题重命名或移动后的关联不确定时需要核查，不能凭相似文本自动继承掌握记录。
未经提交的编辑可预览；提交并登记后才能将其记成新的已读来源。全文件旧来源继续兼容，生成时按原提交派生章节来源，不改写旧事件。
## 题目质量
材料先出题，再由同一指定模型独立执行一轮审题；插件继续检查来源、题型、评分要点、明确的概念复述题与重复目标。允许少出题或不出题，并保存未出题原因。模型审查不能保证学术正确性，题目仍由用户确认后启用。
优先机制因果、错误诊断、代码追踪、反例、条件变化和方案取舍。每题必须提供自洽条件、检验价值、至少两个评分要点和典型误区。避免“XX 是什么”、照搬笔记摘要、为了数量提出重复问题。
“反馈题目质量”支持太浅、重复、题意不清、暂时超纲。反馈进入后续出题输入并可触发重新准备，不计作答失败。旧卡片不每天重新生成，实质修订通过原卡片 ID 与内容版本接受。
## 自动材料与输入范围
新设备的分享与自动运行开关默认关闭；本次已授权设备可开启“允许向 Codex 分享限定的复习输入”和“启动时自动准备复习材料”。许可、CLI 路径、固定会话 ID 与任务状态仅保存在本机，不随 Vault 同步。
输入包括待处理 Request 对应的当前章节来源及前后变化、同文件父级或邻接章节、`.agents/Context.md`、`AgentProtocol.md`，以及已有卡片的目标、问题、状态、到期时间、复习次数和明确提交的题目质量反馈。插件不把自由文本作答、Codex 历史日志或认证凭证装入提示词；CLI 使用本机已配置的认证和服务。
任务处理所有未完成来源，不限“昨天”。每批最多 8 个章节、20 MB 输入；单次 CLI 进程最多 20 分钟。这些是后台任务保护，不是复习时长限制。失败按退避间隔最多自动尝试 3 次，之后可手动重试；关闭分享或停止任务会取消后续批次。
后台使用 `codex exec`，无需等待终端输入。模型返回结构化内容，插件负责打包、哈希校验和归档。恢复固定会话时也显式指定模型与强度。新会话或重置仅影响本机任务，不删除旧 Codex 历史。
## 归档与编辑
`Chores/reviewDocs/YYYY-MM-DD/Review.md` 是当天安排；每批材料存入该日期下的独立目录，包含 `Review.md`、`Exercises.md`、`Changes.md`。答案默认折叠；实际评分后单独生成 `Records/<event_id>.md`。生成时间、提交归档时间、真实作答时间分别记录。
“历史归档”可以直接打开材料，使用 Obsidian 原生 Markdown 编辑器搜索或补充。每日安排若已被手工修改，更新版写入 `Review.Generated-<hash>.md`，保护人工正文。发布后的候选包不可修改，修订用新包。
复习页支持 `Ctrl+F` 页内搜索；“当前学习上下文”位于可展开的后台状态区，以 Markdown 渲染，可打开原文编辑。
## 外部 Agent 协作
外部 Agent 仍可按 `AgentProtocol.md` 发布候选包。自动生成的题目直接进入页面，其他包通过“后台任务与设置状态 → 其他外部成果包”审阅。用户确认前不会创建正式卡片，模型输出也不能直接生成评分事件。
## 常见问题
- 0 张：来源不等于题目，先手动建卡或接受外部题目包。
- 没有来源：确认学习来源前缀和 Git 已提交，再登记最近 7 次提交。纯工作区改动不属于已提交版本。
- 快照期间文件变化：停止编辑稍候，重新执行 Git 补提交检查；不要关闭快照一致性保护。
- 暂存区已有内容、Git 锁、合并中、Hook/签名要求：先按提示处理普通 Git 操作，插件不夺取锁、不覆盖暂存内容。
- 撤回提交后扫描游标不在历史中：执行“登记最近 7 次提交中的学习变化”重新建立扫描范围；已撤回提交对应的来源只可作为历史证据，不能直接激活。
- 来源变更：Agent 根据新来源生成修订包，用户确认后接受，不沿用失效答案。
- 同步与迁移：本目录和根 Context 应被 Git 跟踪，缓存位于操作系统用户数据目录。不要忽略整个 .obsidian，也不要将两台设备同时设为写入设备。
- 0.1.0 升级：首次打开新默认目录且没有身份文件时，复制旧 LearningReview 的内容，身份最后落盘；冲突停止，原目录不删除。确认迁移完成后旧目录可由用户自行归档，避免同时编辑两份。
