## Qt 相关
### QPointer 和 STL 中的智能指针
**1. QPointer vs C++ 智能指针**

首先，QPointer **不是智能指针**——它不管理生命周期，只做**弱引用**。

|           | `unique_ptr`     | `shared_ptr`      | `weak_ptr`           | `QPointer<T>`      |
| --------- | ---------------- | ----------------- | -------------------- | ------------------ |
| **管理所有权** | 独占，自动 delete     | 共享，引用计数归零时 delete | 不管理                  | 不管理                |
| **防止悬空**  | 转移所有权，不存在"用已删对象" | 引用计数保证对象存活        | `lock()` 检查对象是否存活    | 对象析构时自动置 `nullptr` |
| **限制**    | —                | —                 | 必须配合 `shared_ptr` 使用 | T 必须是 QObject 子类   |
| **实现依赖**  | 模板元编程            | 控制块 + 原子计数        | 依赖控制块                | 依赖 QObject 析构函数通知  |

**本质区别：** C++ 智能指针用**引用计数/所有权**管理生命周期，`weak_ptr` 通过检查控制块存活状态来判断悬空。QPointer 则完全不参与生命周期——它只是被 QObject 析构时通知"我没了，把你的值置 null"。

**记忆点：** `shared_ptr/weak_ptr` 是"我数着还有多少人用你"，`QPointer` 是"你死的时候记得告诉我一声"。前者需要对象配合引用计数，后者需要对象继承 QObject。
### Qt MOC 系统的理解
**支柱一：信号槽**
**支柱二：运行时类型信息**

每个 `QMetaObject` 有一个 `superClass()` 指针指向父类的 `staticMetaObject`，形成**元对象链表**。`qobject_cast` 遍历这个链表做指针比较，而非字符串比较。比 `dynamic_cast` 快且跨编译器行为一致。

**关键词：** 元对象链表、指针比较而非字符串、跨编译器一致性

**支柱三：属性系统**
**支柱四：动态调用**

```cpp
QMetaObject::invokeMethod(obj, "start", Qt::QueuedConnection, Q_ARG(int, 42));
```

通过方法名字符串查找 `QMetaMethod`，然后构造调用。MOC 为每个信号/槽/ `Q_INVOKABLE` 方法生成 `qt_static_metacall` 辅助函数——内部是个巨大的 switch，按方法索引分发到真正的方法调用。

**注意：** 方法名解析有开销，所以提供了索引重载 `invokeMethod(obj, method_index, ...)` 来绕过字符串查找。这是 Qt 常见优化手段。

**关键词：** qt_static_metacall + switch 索引分发、运行时按名称或索引调用、Q_INVOKABLE
**四个支柱的共同基础：**

```
Q_OBJECT 宏

    →  MOC 生成 .moc 文件
    →  填充 QMetaObject 的所有字段
```

### 什么是指针
- 指针是一个 4 字节或 8 字节的整型数，本身大小和 CPU 位数有关，其中存储一个内存地址，读取指针，也就是 `*` 解引用指针操作会访问以这个内存地址做开头，长度为指针类型长度的一段内存块 
- 指针的还允许 cv 修饰符修饰，控制指向是否可以改变或者是否可以通过指针修改指向内存块
- 一般来说，C 中使用 malloc ，C++中使用 new 可以创建一个在栈上存储的指针，指向一个堆内存的地址
- 指针支持运算，规则是从指针指向的起始地址向前或者向后移动指针类型大小长度的内存。有一个特殊情况成员函数指针占用两个指针大小，不能转换为 void 也不能进行运算，因为类有可能多重继承
- 使用 delete 或者 free 会将指针指向的内存归还给操作系统内存池，但 free 函数只根据指针元数据控制头中的信息归还内存，不会调用析构函数，delete 会调用指针指向对象的析构函数，然后调用 free 回收内存，如果是数组要调用 `delete[]`，delete 还支持 `operator` 关键字自定义删除逻辑
### 操作系统
堆和栈的起始地址是内存的什么位置？他们的生长方向是什么样的？
堆和栈的内存位置与生长方向
```
  高地址 0x7FFFFFFFFFFF
  ┌────────────────────┐
  │   内核空间           │
  ├────────────────────┤ ← 用户空间顶部
  │   栈 (stack)        │ ← 从高地址开始
  │       ↓ 向下生长    │    栈指针递减
  │                    │
  │   ...空闲...       │ ← 栈和 mmap 区域之间
  │                    │
  │   mmap 区域         │ ← 共享库、文件映射、大块匿名映射
  │       ↓ 向下生长    │
  │                    │
  │   ...空闲...       │
  │                    │
  │   堆 (heap)         │ ← sbrk 扩展
  │       ↑ 向上生长    │
  ├────────────────────┤
  │   BSS (未初始化数据) │
  ├────────────────────┤
  │   Data (已初始化数据) │
  ├────────────────────┤
  │   Text (代码段)      │ ← 只读
  └────────────────────┘
  低地址 0x400000 左右
```
记忆点：
```
  ┌──────────┬────────────────────────────────────┬──────────────────────┐
  │          │                 栈                 │          堆          │
  ├──────────┼────────────────────────────────────┼──────────────────────┤
  │ 起始位置  │ 用户空间顶部（高地址）                 │ BSS 段之后（低地址）    │
  ├──────────┼────────────────────────────────────┼──────────────────────┤
  │ 生长方向  │ 向下（地址递减）                      │ 向上（地址递增）        │
  ├──────────┼────────────────────────────────────┼──────────────────────┤
  │ 相对运动  │ 栈和堆相向生长，中间还有 mmap 区域      │                      │
  └──────────┴────────────────────────────────────┴──────────────────────┘
```

  栈向下生长的原因： 历史设计。栈从高地址向下，堆从低地址向上，中间的空间可以被两者共享——早期内存很小的
  时候这很实用。现代这种设计仍然保留，但两者一般不直接碰撞，因为它们之间有 mmap 区域做缓冲。
