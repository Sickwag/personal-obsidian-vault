#### 技术面
**一、把一个 `list<pair<int, int>>` 去重，输出到 `vector<pair<int, int>>`**
答题要点：
- 先问一句"要不要保持原来的顺序"，这一步决定用哪个容器，面试官要的就是这个判断。
- 保序：遍历 list，用哈希集合记录"见过的"，第一次出现才 push 进 vector，O(n)。
- 不要求保留原顺序：直接构造 `std::set<std::pair<int,int>>`，结果是按 `pair` 的字典序排好的，O(n log n)，`pair` 自带 `operator<`。
- 关键坑：`pair` **没有现成的 `std::hash` 特化**（C++20 也没有），要用 `unordered_set` 必须自己写 hash 函数。
代码：
```cpp
struct PairHash {
    std::size_t operator()(const std::pair<int, int>& p) const noexcept {
        std::size_t h1 = std::hash<int>{}(p.first);
        std::size_t h2 = std::hash<int>{}(p.second);
        // 黄金比例常数打散，避免 (1,2) 和 (2,1) 落到同一个桶
        return h1 ^ (h2 + 0x9e3779b97f4a7c15ULL + (h1 << 6) + (h1 >> 2));
    }
};
// 1) 保序去重
std::vector<std::pair<int, int>> dedupKeepOrder(const std::list<std::pair<int, int>>& l) {
    std::vector<std::pair<int, int>> out;
    std::unordered_set<std::pair<int, int>, PairHash> seen;
    out.reserve(l.size());
    for (const auto& p : l)
        if (seen.insert(p).second) out.push_back(p);   // insert 返回 {迭代器, 是否插入成功}
    return out;
}
// 2) 不保序但有序
std::vector<std::pair<int, int>> dedupSorted(const std::list<std::pair<int, int>>& l) {
    std::set<std::pair<int, int>> s(l.begin(), l.end());
    return std::vector<std::pair<int, int>>(s.begin(), s.end());
}
// 3) 不用哈希表：先排序再 unique
std::vector<std::pair<int, int>> dedupSort(std::list<std::pair<int, int>> l) {
    std::vector<std::pair<int, int>> v(l.begin(), l.end());
    std::sort(v.begin(), v.end());
    v.erase(std::unique(v.begin(), v.end()), v.end());
    return v;
}
```
- 复杂度：哈希版 O(n) 期望、O(n log n) 最坏；set 版 O(n log n) 且额外内存；排序版不改输入时也要 O(n) 额外内存。
追问：
- Q: 为什么标准库不给 `pair` 提供 hash？
- A: 组合哈希没有唯一正确做法（拼接顺序、冲突质量都会变），标准库只保证标量/字符串等基础特化，`pair`/`tuple` 让用户按场景自己组合。
- Q: 如果要保留第一次出现的位置，但又想省内存？
- A: 数据量小时排序去重更省（无哈希表），但要额外记原下标才能还原顺序；两头都要就只能上哈希集合。
**二、两数之和（返回下标）**
答题要点：
- 哈希表存"已经见过的值和下标"，遍历时查 `target - x`，命中就返回，O(n) 时间、O(n) 空间。
- **先查后插**：否则 `[3,3], target=6` 会把同一个元素用两次。
- 返回值语义先确认：无解返回空 vector 还是 {-1,-1}。
代码：
```cpp
std::vector<int> twoSum(const std::vector<int>& nums, int target) {
    std::unordered_map<int, int> seen;      // 值 -> 下标
    for (int i = 0; i < static_cast<int>(nums.size()); ++i) {
        auto it = seen.find(target - nums[i]);
        if (it != seen.end()) return {it->second, i};
        seen.emplace(nums[i], i);           // 先查后插
    }
    return {};
}
```
追问：
- Q: 数组有序怎么做？
- A: 双指针，`l + r < target` 就左移，反之右移，O(n) 时间 O(1) 空间；代价是丢了原下标（要下标就存 (值, 原下标) 再排序）。
- Q: 要返回所有不重复的解？
- A: 排序后固定第一个数，剩下双指针；跳过相邻重复值去重，注意"同一元素不能用两次"的判断。
**三、四、设计函数把 `map` 遍历一遍，把 key 和 value 一起取出来**
答题要点：
- 这两条面经是转写，题干不完整（"给定一个函数，返回 vector 里面两个 int，map 输入是两个 int"）。第一步一定是确认签名：输入是 `map<int,int>`，还是 `map<pair<int,int>, V>`？输出是 `vector<pair<...>>` 还是两个数组？
- 通用写法：一次遍历 + `reserve` + 结构化绑定，别用 `operator[]`。
代码：
```cpp
// 情况 A：输入 map<int,int>，输出 vector<pair<int,int>>
std::vector<std::pair<int, int>> flatten(const std::map<int, int>& m) {
    std::vector<std::pair<int, int>> out;
    out.reserve(m.size());                       // 一次分配，避免扩容
    for (const auto& [k, v] : m) out.emplace_back(k, v);
    return out;
}
// 情况 B：拆成两个数组
void split(const std::map<int, int>& m, std::vector<int>& keys, std::vector<int>& vals) {
    keys.reserve(m.size());
    vals.reserve(m.size());
    for (const auto& [k, v] : m) { keys.push_back(k); vals.push_back(v); }
}
// 情况 C：key 本身是两个 int
std::vector<std::pair<std::pair<int, int>, int>>
flattenPairKey(const std::map<std::pair<int, int>, int>& m) {
    std::vector<std::pair<std::pair<int, int>, int>> out;
    out.reserve(m.size());
    for (const auto& [k, v] : m) out.emplace_back(k, v);
    return out;
}
// 情况 D：函数返回 vector 里的两个 int 当 map 的 key
std::pair<int, int> makeKey(const std::vector<int>& v, std::size_t i) {
    return {v.at(i), v.at(i + 1)};               // at 会做边界检查
}
```
追问：
- Q: 遍历时为什么不能用 `m[k]`？
- A: `operator[]` 是非 const 成员，键不存在会插入默认值，遍历过程被改；读用 `find`/`at`，遍历用范围 for。
- Q: `map` 和 `unordered_map` 遍历顺序？
- A: `map` 按 key 升序（红黑树中序遍历），`unordered_map` 顺序取决于哈希和桶，不可预期；要稳定输出就排序或用 `std::map`。
**五、六、读 LLVM `StringRef` 源码：它和 `std::string` 有什么区别？**
答题要点：
- `StringRef` 是**非拥有视图**，内部只有 `const char* Data` 和 `size_t Length` 两个成员：不分配、不拷贝、构造和拷贝都是 O(1)；不保证以 `\0` 结尾。
- `std::string` **拥有**内存（小字符串走 SSO 内联），可修改，生命周期自己管。
- 设计目的：函数入参用 `StringRef` 能同时接受 `const char*`、`std::string`、字面量、子串，且一律零拷贝；返回值/成员变量才用 `std::string`。
- 风险：视图悬垂。`StringRef s(std::string("tmp"));` 或对临时对象取 `.str()` 之外的引用，临时对象一析构，`s` 就是野指针。也不能把它直接传给 `printf("%s")`/`strlen`。
- 对标：它就是 C++17 的 `std::string_view` 的前身（LLVM 更早），多了 `startswith/endswith/trim/split/consume_front/consume_back` 这些便利方法。
- 源码证据：`begin()` 返回 `Data`、`end()` 返回 `Data + Length`；`bytes()` 也是用 `data()` 和 `size()` 造区间——全程不分配。
追问：
- Q: `StringRef` 能拼接吗？
- A: 不能直接拼（没有所有权、放不下结果）。拼接要么 `Twine`/`std::string`，要么用 `operator+` 生成新的 `std::string`。
- Q: 为什么函数参数写 `StringRef` 而不是 `const std::string&`？
- A: 后者接受 `const char*` 时会先构造一个临时 `std::string`（可能分配），`StringRef` 直接就是指针 + 长度；而且能接受子串，不产生中间对象。
**七、`static constexpr size_t npos = ~size_t(0);` 里三个关键字分别什么作用**
答题要点：
- `static`：类作用域静态成员，所有对象共享一份，不占对象空间；C++17 起 `constexpr` 静态数据成员**隐含 inline**，类内定义即可，不需要再在类外写一遍定义；访问写 `StringRef::npos`。
- `constexpr`：编译期常量，能出现在常量表达式里（数组大小、模板参数、`case` 标签），运行期零开销；同时隐含 `const`，不能改。
- `~size_t(0)`：按位取反。`size_t(0)` 全 0，取反后全 1，就是 `SIZE_MAX`，用作"没找到"的哨兵值。
- 为什么不用 `-1`：`size_t` 是无符号类型，`-1` 要先做隐式转换，语义含混、有的编译器会警告；`~size_t(0)` 是无符号运算、编译期可算、不触发警告。
- 为什么类型必须是 `size_t`：`size()`/`find()` 的返回类型都是 `size_t`，同类型比较不会发生整型提升/符号扩展。
追问：
- Q: `npos` 具体是多少？怎么用？
- A: 64 位下是 `18446744073709551615`。`find` 找不到返回它，所以判断写 `if (pos == StringRef::npos)`，不能写 `pos < 0`。
- Q: `static constexpr` 和 `constexpr` 成员函数里的 `static` 是一回事吗？
- A: 不是。这里是**静态数据成员**的存储期说明；类里 `static` 成员函数是没有 `this` 的函数，两者作用完全不同。
**八、反向迭代器（`reverse_iterator`）是怎么工作的**
答题要点：
- `std::reverse_iterator<It>` 是适配器，内部保存一个 base 迭代器，解引用时"先减一再取值"，所以 `*r == *(it - 1)`。
- 因此 `rbegin() = reverse_iterator(end())`、`rend() = reverse_iterator(begin())`；`r.begin().base() == end()`。
- 这个"错位"是设计使然：让 `[rbegin(), rend())` 和正向区间一一对应，`rbegin()` 指向最后一个元素，`rend()` 是"第一个元素之前"。
- 用途：`std::sort(v.rbegin(), v.rend())` 降序；`rfind`、`rsplit`、`rtrim` 这类从尾部处理的实现。
- 坑：只对双向迭代器有效；`rbegin()` 不能直接和 `begin()` 比，要先 `.base()`；空容器里 `rbegin() == rend()` 成立，但解引用依然非法。
代码：
```cpp
template <class It>
class ReverseIt {
    It cur_;
public:
    explicit ReverseIt(It it) : cur_(it) {}
    auto operator*() const { It tmp = cur_; return *--tmp; }   // 先减一再取
    ReverseIt& operator++() { --cur_; return *this; }
    bool operator!=(const ReverseIt& o) const { return cur_ != o.cur_; }
};
std::vector<int> v{1, 2, 3};
ReverseIt<std::vector<int>::iterator> r(v.end()), re(v.begin());   // 3 2 1
```
追问：
- Q: 反向迭代器的 `base()` 指向哪？
- A: 指向"当前元素的下一个位置"：`(*r)` 实际是 `*(r.base() - 1)`，`r.base()` 本身指向前方一个元素。
- Q: 为什么 `erase`/`insert` 不能用反向迭代器？
- A: 容器接口只接受正向迭代器（`const_iterator`/`iterator`），反向迭代器是适配器，要先用 `.base()` 换回去，注意此时位置要再调整一位。
**九、读代码：`compareMemory`、`bytes()`、`xxh3_64bits(StringRef)` 分别在干什么**
答题要点：
- `compareMemory(Lhs, Rhs, Length)`：带 0 长度短路的 `memcmp` 包装。长度 0 直接返回 0——既省一次调用，也避开"把可能为空的指针传给 `memcmp`"这个标准上不干净的点；它被 `compare()` 用来做前缀比较。
- `bytes()`：把字符串内容按**无符号字节**暴露成迭代器区间 `iterator_range<const unsigned char*>`。为什么必须转 `unsigned char`：`char` 的符号性依平台而定（x86 有符号、ARM 常无符号），哈希/加密/序列化要按无符号字节算，否则同一份内容在不同平台算出不同结果。
- `xxh3_64bits(StringRef)`：给 `StringRef` 算 XXH3 64 位哈希的适配层，内部 `reinterpret_cast<const uint8_t*>(data.data())` + `data.size()` 调底层实现。它正好体现 `StringRef` 的设计意图：**只传指针 + 长度，不假设 `\0` 结尾，不拷贝**。
- XXH3 是非加密哈希，速度比 MD5/SHA 快一到两个数量级，适合哈希表、去重、快速校验；不能用于密码学场景。
追问：
- Q: 为什么哈希函数签名用 `StringRef` 而不是 `const std::string&`？
- A: 调用方不用为了传参构造 `std::string`（否则每次哈希都分配一次），也能直接哈希字面量和子串。
- Q: 如果字符串里含 `\0`，`StringRef` 还能正确表示吗？
- A: 能。`StringRef` 带长度，`(ptr, len)` 构造可表示任意字节序列；但用 `const char*` 隐式构造时会按 `strlen` 截断，这点要小心。

**十一、Linux 环境下怎么导入环境变量**
答题要点：
- 临时（当前 shell 和它启动的子进程）：`export NAME=value`；只对一条命令生效：`NAME=value cmd`。
- 永久：登录 shell 读 `/etc/profile`、`~/.profile`/`~/.bash_profile`；交互式 bash 读 `~/.bashrc`；zsh 读 `~/.zshrc`；系统级 `/etc/environment`（由 PAM 读取，只认 `KEY=value`，不支持变量展开）。
- 查看：`echo $NAME`、`printenv NAME`、`env | grep NAME`。
- 追加而不是覆盖：`export PATH="$PATH:/opt/toolchain/bin"`（写反了会顶掉系统命令）。
- 立即生效：`source ~/.bashrc`（`source` 等价于 `.`）。
- 子进程继承：`fork/exec` 时复制环境表，父导出子能见、子改了父看不见。
代码：
```sh
export CC=gcc CXX=g++
export PATH="/opt/toolchain/bin:$PATH"
export LD_LIBRARY_PATH="/opt/toolchain/lib:$LD_LIBRARY_PATH"
export C_INCLUDE_PATH=/opt/toolchain/include
source ~/.bashrc
printenv | grep -E '^(CC|CXX|PATH|LD_LIBRARY_PATH)='
```
追问：
- Q: 交叉编译时环境变量怎么起作用？
- A: `PATH` 决定用哪套 `gcc/as/ld`，`CC/CXX` 决定构建系统调用谁，`sysroot`/`--sysroot` 决定找目标平台的头文件和库；CMake 里对应 `CMAKE_C_COMPILER`、`CMAKE_SYSROOT`。
- Q: `LD_LIBRARY_PATH` 和链接时找库的路径是一回事吗？
- A: 不是。链接时用 `-L`（或 `LIBRARY_PATH`）找 `.so`，运行时用 `LD_LIBRARY_PATH`、`rpath`、`ld.so.cache` 找已经链接的库。
- Q: 为什么 `sudo` 之后环境变量没了？
- A: sudo 默认 `env_reset` 清空环境，`sudo -E` 或 `env_keep` 可保留；systemd 服务同理不读 `~/.bashrc`，要用 `Environment=`/`EnvironmentFile=`。

- 别踩：不要硬气说"我不加班"，也不要拍胸脯"随便加"——两个极端都会被扣分。
**五、学习或比赛时有没有压力大的时候？怎么调节？**
答题要点：
- 真实场景：竞赛/项目 deadline 撞在一起，或者一个 bug 卡了一整天。
- 方法：把大任务拆成清单，每次只推一件；卡住就先换任务或找人讲一遍；固定作息 + 运动（跑步/健身房），不靠熬。
- 给结果：比如比赛里卡题时换题、分工，最后拿到铜牌；或者 bug 通过写最小复现解决。
- 别踩：别说"我没什么压力"（不真实），也别把压力来源全归到外部。
**六、你手里有其它实习 offer 吗？为什么还看其它实习？**
答题要点：
- 按实际答，不撒谎：如果有就说"有/在流程中"，如果没有就说"目前有几个在流程里，还没到最后"。
- 为什么还看：我优先看方向——工具链/底层这类岗位本来就少，所以会多看几家；不是海投，是有选择地投。
- 选择标准排序：方向 > 带教和人 > 薪资；说清"如果方向对，我愿意长期做"。
- 别踩：不要贬低别家；不要说"我就是来练面试的"；也不要编造 offer（被追问细节就露馅）。
**七、你对实习薪资有什么要求？（说了"服从安排"后 HR 会追问范围）**
答题要点：
- 先反问结构：是日薪还是月薪？有没有餐补/住宿/交通补贴、加班怎么算。
- 给范围（准备好的数字，按上海 C++ 实习行情）：例如"我了解上海这边 C++ 实习大概 200 到 300 一天，我的期望是 200 到 250 一天（或对应的月薪），主要考虑租房和通勤"。
- 收尾表态：公司有自己的标准，按标准来我都能接受，我更看重能不能学到东西。
- 别踩：只答"服从安排"会被追着问，必须有一个数；也不要报得明显高于行情显得不了解市场。
**八、通过业务面试你应该了解公司方向了，对公司方向有什么看法，能接受吗？**
答题要点：
- 行业层面：国产芯片和自主可控是长期方向，DSP 用在音频、通信、工业控制这些场景，工具链是生态短板，做这块有实际价值。
- 公司层面：创业阶段，节奏快、能参与从 0 到 1，也能看到整个工具链怎么搭起来；这类机会在大公司反而难碰到。
- 明确接受：我就是想做底层工具，能接受这个方向。
- 别踩：不要评价公司前景/融资/规模，不要说"传统行业没意思"这类对其他方向的贬低。
**九、讲 1-2 个项目中遇到的难题，你怎么解决的？**
答题要点：
- 第一个（技术型）：协程挂死（同上，1 分钟精简版：现象 → 三步定位 → 修法 → 收获）。
- 第二个（业务/协作型）：xTubeNest 里偏置后的轮廓自交、孔前端轮廓重复，靠先做最小几何用例复现、再改算法并加回归用例解决；或者 IM 项目里多端登录的竞态，用原子操作 + 会话版本号解决。
- 两个故事要有区别：一个偏底层排障，一个偏业务建模/协作，别都是框架。
- 别踩：不要说"没有遇到难题"；也不要讲一个最后没解决的问题（除非说清学到了什么）。
**十、你是哪里人？有兴趣来上海发展吗？对上海有什么看法**
答题要点：
- 模板：我是<你的籍贯>人，家里支持我出来实习；上海这边芯片和软件公司多，机会比老家好，我打算毕业后在这边发展。
- 对上海的看法：节奏快、通勤时间长，但行业密度高；我已经了解过租房的大致成本，能接受。
- 别踩：不要只说"上海很好"（空），也不要抱怨房租贵、加班多（还没入职就抱怨）；别说"先看看，不行就回家"。
**十一、什么时候能来实习？能实习多久？**
答题要点：
- 给一个具体日期（例如 12 月中旬、或学校课程/考试结束后的第一周），并说明怎么协调学校的事。
- 时长：6 个月以上；如果学校有毕设/答辩，说清那段时间怎么安排（远程/请假/提前沟通）。
- 别踩：不要"随时都行"（显得没规划），也不要给一个模糊的"过完年再说"。
**十二、你有什么想问我的？**
答题要点：
- 从上面「反问」里挑两条最相关的：① 团队工具链是基于 LLVM/GCC/newlib 改还是自研；② 带我的同事主要做编译器还是模拟器/调试器。
- 再加一条针对刚才面谈内容的即时问题，比如"刚才您提到的模拟器/调试器部分，新人一般从哪块开始接手？"
- 收尾问一句流程：下一轮大概什么时候、需要我提前准备什么。
- 别踩：不在技术/性格面问薪资、加班、转正（这些留到 HR 面，本文件「通用反问」里已经准备好）；不要问"公司会不会倒闭""你们加班多吗"这类容易掉分的问题。

# 通用反问
- 我的具体工作是什么？或者说现阶段我能为公司做什么？
- 有没有转正名额？转正之后的的工作内容有又是什么？
- 有没有试岗期，时长多久（1 年->不能超过 2 月）
- hr 向我说明过公司更希望长期实习然后转正一直留在公司这个情况，那么贵公司对我这样的实习生有没有什么培养计划？
- 假设我入职之后，会进入哪个团队呢？- 实习期考核内容是什么？如何公司对我这样的实习生期待是什么？
- 上班时间是怎么样的？
- 如果对方提到了加班：
	- 愿意接受加班，如果是自己职责范围的工作，那就不算加班，加班只是过程，解决问题，降本增效才是工作的目的，在工作中我会尽我的能力去寻找高效的工作方法，减少无效的工作
	- 举个🌰：首先，如果确实项目紧急或者确实是我能力不够，必要的加班我是可以理解的。加班是态度，不加班是能力，在我能力还不够或者初来乍到的时候，我愿意用积极的态度来弥补。其次，我和公司一样注重效率，不排斥加班，但也不赞成没有意义的加班。毕竟工作最终是靠结果说话的。
	- 顺便也想了解一下，这个岗位平时的加班情况怎么样？一般什么情况下需要加班？团队其他同事的加班频率如何？这样我可以提前做好心理准备。
- 面试完后什么时候能告知我结果呢？每天的工作是什么？
