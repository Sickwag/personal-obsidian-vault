## 第 1 题：老鹰捉小鸡

**笔试时间：** 2026 年 5 月 6 日

**题目：**

游戏开始时有 `m` 只小鸡，按给定顺序组成队列，每只小鸡编号唯一。游戏共进行 `n` 轮。每轮中，老鹰攻击当前队列中第 `a` 只小鸡，鸡妈妈保护第 `b` 只小鸡，位置均从 `1` 开始。

- 若攻击位置超过当前队列长度，攻击无效。
- 若保护位置超过当前队列长度，保护无效。
- 若攻击和有效保护指向同一个位置，攻击失败；否则有效攻击成功，该小鸡离队，后面的小鸡依次前移。
- 每轮后若小鸡数量小于等于 `1`，游戏立即失败；否则所有轮次结束后游戏胜利。

失败时输出 `Fail!` 和剩余小鸡编号；胜利时输出 `Success!` 和所有剩余小鸡编号，编号按递增顺序排列。

### 输入描述

输入共三行：

- 第一行两个整数 `m, n`，表示初始小鸡数量和操作轮数。
- 第二行 `m` 个整数，表示小鸡队列初始编号。
- 第三行 `2n` 个整数，每两个为一组，依次表示攻击位置和保护位置。

数据范围：`2 ≤ m ≤ 1000`，`1 ≤ n ≤ 1000`。

### 输出描述

按题意输出失败或胜利信息。感叹号后有一个空格。

|   |   |
|---|---|
|1<br><br>2<br><br>3| `4` `3`<br><br>`40` `30` `20` `10`<br><br>`2` `1` `2` `1` `1` `1` |

### 样例输出

[复制代码](#)

### 样例说明

### 参考题解

参考实现见下方 C++、Java、Python 三种完整程序；核心推导如下。

#### 解题思路

用可删除的顺序表直接模拟队列。每轮操作必须以该轮开始时的队列长度判断位置是否有效。有效攻击仅在保护位置也有效且两个位置相同时失败，其余情况删除被攻击元素。

若用数组实现，单次删除最坏 `O(m)`，总时间复杂度 `O(mn + m log m)`，空间复杂度 `O(m)`。

```cpp
int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int m, n;
    cin >> m >> n;
    vector<long long> q(m);
    for (auto &x : q) cin >> x;
    for (int round = 0; round < n; round++) {
        int attack, protect;
        cin >> attack >> protect;
        int length = (int)q.size();
        if (attack <= length && !(protect <= length && attack == protect)) {
            q.erase(q.begin() + attack - 1);
        }
        if (q.size() <= 1) {
            for (++round; round < n; round++) cin >> attack >> protect;
            break;
        }
    }
    if (q.size() <= 1) {
        cout << "Fail!";
        for (long long x : q) cout << ' ' << x;
    } else {
        sort(q.begin(), q.end());
        cout << "Success!";
        for (long long x : q) cout << ' ' << x;
    }
    cout << '\n';
    return 0;
}


```

vector<vector<double>> parseMatrix(string text) {
    size_t l = text.find('['), r = text.rfind(']');
    string body = text.substr(l + 1, r - l - 1);
    vector<vector<double>> a;
    string row;
    stringstream rows(body);
    while (getline(rows, row, ';')) {
        stringstream ss(row);
        vector<double> values;
        double x;
        while (ss >> x) values.push_back(x);
        if (!values.empty()) a.push_back(values);
    }
    return a;
}
double exponentOf(double x) {
    double p = 1.0, k = 0.0;
    while (p + 1e-12 < x) p *= 2.0, k += 1.0;
    return k;
}
vector<vector<double>> gram(const vector<vector<double>>& a) {
    int n = a.size(), m = a[0].size();
    if (n >= m) {
        vector<vector<double>> g(m, vector<double>(m));
        for (int i = 0; i < n; i++)
            for (int p = 0; p < m; p++)
                for (int q = p; q < m; q++) g[p][q] += a[i][p] * a[i][q];
        for (int p = 0; p < m; p++) for (int q = 0; q < p; q++) g[p][q] = g[q][p];
        return g;
    }
    vector<vector<double>> g(n, vector<double>(n));
    for (int i = 0; i < n; i++) for (int j = i; j < n; j++) {
        for (int k = 0; k < m; k++) g[i][j] += a[i][k] * a[j][k];
        g[j][i] = g[i][j];
    }
    return g;
}
vector<double> jacobi(vector<vector<double>> a) {
    int n = a.size();
    for (int it = 0; it < max(50, 100 * n * n); it++) {
        int p = 0, q = n > 1 ? 1 : 0;
        double best = 0;
        for (int i = 0; i < n; i++) for (int j = i + 1; j < n; j++)
            if (abs(a[i][j]) > best) best = abs(a[i][j]), p = i, q = j;
        if (best < 1e-12) break;
        double app = a[p][p], aqq = a[q][q], apq = a[p][q];
        double tau = (aqq - app) / (2 * apq);
        double t = copysign(1.0 / (abs(tau) + sqrt(1 + tau * tau)), tau);
        double c = 1 / sqrt(1 + t * t), s = t * c;
        for (int k = 0; k < n; k++) if (k != p && k != q) {
            double akp = a[k][p], akq = a[k][q];
            a[k][p] = a[p][k] = c * akp - s * akq;
            a[k][q] = a[q][k] = s * akp + c * akq;
        }
        a[p][p] = c*c*app - 2*s*c*apq + s*s*aqq;
        a[q][q] = s*s*app + 2*s*c*apq + c*c*aqq;
        a[p][q] = a[q][p] = 0;
    }
    vector<double> e(n);
    for (int i = 0; i < n; i++) e[i] = a[i][i];
    return e;
}

    sort(answer.rbegin(), answer.rend());

        if (i) cout << ' ';
        cout << answer[i];
    }
    cout << '\n';
    return 0;

一个 200GB 文件支持并发分片上传、断点续传和秒传，元数据应该怎样设计？
上传会话至少保存文件标识、文件总长度、分片大小、分片数量、内容摘要算法、会话状态和过期时间。每个分片保存序号、实际长度、摘要、存储位置和提交状态，并在 `(upload_id, chunk_no)` 上建立唯一约束，使重复上传同一分片能够幂等覆盖或直接返回成功。

客户端上传分片前可以先提交文件级摘要。服务端若已经存在相同内容且调用方有权引用，可直接建立逻辑文件记录实现秒传，但不能只信任客户端摘要。高安全场景应验证文件长度、抽样分片摘要，或由可信上传链路生成摘要。

合并不能简单地把所有分片一次读入内存。服务端应按照分片顺序流式写入临时文件，同时计算整文件摘要；校验完成后通过原子重命名发布。会话状态需要使用条件更新，确保只有一个合并者从 `UPLOADING` 迁移到 `MERGING`。


C++ 的严格别名规则是什么？下面的类型转换为什么可能被优化器错误处理？
```cpp
float value = 1.0f;
uint32_t bits = *reinterpret_cast<uint32_t*>(&value);
```
C++ 通常不允许通过不兼容类型的左值读取一个对象。编译器可以假设 `float*` 与 `uint32_t*` 不指向同一对象，并据此重排、合并或删除访问。即使两者大小相同，上述解引用也违反严格别名规则，属于未定义行为；对齐满足也不能使它合法。  

`io_uring` 的 SQPOLL、固定文件和固定缓冲区分别解决什么问题？
普通 `io_uring` 由用户态填写提交队列，进入内核后提交请求。SQPOLL 会创建内核轮询线程读取提交队列，在活跃期内可以减少提交请求所需的系统调用，但会占用 CPU，并受到权限、空闲超时和 NUMA 位置影响。

固定文件预先把文件描述符注册到 ring，提交时使用注册表索引，减少每次请求查找和获取文件对象引用的开销。固定缓冲区预先注册用户内存，减少重复页固定和地址校验成本。

它们并不等于请求天然零拷贝。文件读到用户缓冲区仍然发生数据传输；网络发送是否零拷贝取决于具体操作和内核支持。固定资源还会增加生命周期约束：请求完成前不能释放或替换相关内存，文件注册表更新也必须和在途请求协调。

5. C++20 原子等待 `atomic::wait` 如何避免条件变量中的丢失唤醒？

**答案：**

`atomic::wait(old)` 只有在原子值仍等于 `old` 时才阻塞。实现会在进入内核等待前再次检查值，因此通知发生在检查与休眠之间时，等待线程也能观察到值已经变化，不会永久睡眠。

通知本身不携带内存同步语义，数据发布仍需通过原子变量的 release/acquire 建立 happens-before。
```
#include <atomic>
#include <string>

std::string payload;
std::atomic<int> state{0};

void producer() {
    payload = "ready";
    state.store(1, std::memory_order_release);
    state.notify_all();
}

void consumer() {
    int expected = 0;
    while (state.load(std::memory_order_acquire) == 0) {
        state.wait(expected, std::memory_order_relaxed);
    }

    // acquire 读取到 1 后，可以安全读取 payload
    use(payload);
}
```

等待仍应写成循环，因为实现允许无关唤醒，而且状态可能在唤醒后再次变化。`notify_one` 也不保证公平性。

6. 一个无界 MPMC 队列即使逻辑正确，为什么仍可能在线上耗尽内存？

**答案：**

无界队列只保证生产者可以持续入队，不保证消费者具有相同处理能力。当生产速率长期高于消费速率时，排队数量线性增长。每个节点除了业务数据，还包含分配器元数据、指针和对齐填充；跨线程释放还可能使内存停留在线程缓存中，因此 RSS 增长会比有效负载更快。

正确设计需要容量和过载语义。可以设置队列高低水位，在高水位停止上游读取；也可以按请求优先级拒绝、采样或落盘。容量不应只按元素个数计算，还应考虑字节数，因为单个任务大小可能差异很大。

并发队列还要避免生产者只检查容量后再入队造成超卖。容量令牌应通过原子计数或信号量在入队前获取，出队后归还。若任务跨多个流水线阶段，每一段都必须有限，否则背压会在下一段重新失效。

7. 解释 ELF 符号插桩、PLT/GOT 和 `LD_PRELOAD` 的调用链

**答案：**

位置无关代码调用外部函数时，通常通过 PLT 跳板间接访问。首次调用在惰性绑定模式下进入动态链接器，解析符号地址后把结果写入 GOT，后续调用直接通过 GOT 跳转。

`LD_PRELOAD` 指定的共享库会被优先加入符号查找范围，因此可以提供同名函数截获调用。包装函数若需要调用原实现，可以通过 `dlsym(RTLD_NEXT, "malloc")` 查找当前对象之后的下一个定义。

但这种方法并非对所有调用有效。静态链接、隐藏符号、`-Bsymbolic`、编译器内联以及直接绑定都可能绕开插桩。包装 `malloc` 时还要特别避免递归，因为 `dlsym`、日志函数和 C++ 容器本身都可能再次分配内存。
```
#define _GNU_SOURCE
#include <dlfcn.h>
#include <cstddef>

extern "C" void* malloc(size_t size) {
    using Fn = void* (*)(size_t);
    static Fn realMalloc =
        reinterpret_cast<Fn>(dlsym(RTLD_NEXT, "malloc"));
    return realMalloc(size);
}

```

这段示例只展示原理，生产实现还必须处理初始化递归、线程安全和 `dlsym` 失败。

8. 使用无符号整数解析网络长度字段时，怎样防止整数溢出绕过边界检查？

**答案：**

危险写法是先计算 `offset + length` 再与缓冲区大小比较。如果加法发生无符号回绕，结果可能变小，从而通过检查。乘法计算元素总长度也有相同问题。

应将检查改写成减法形式，并保证减法本身不会下溢：先验证 `offset <= size`，再验证 `length <= size - offset`。乘法则先判断 `count <= max / elementSize`。


解析协议时还要先完成端序转换，并给长度设置业务上限。即使算术没有溢出，攻击者提供数 GB 的合法长度仍可能造成内存耗尽。

9. Raft 成员变更为什么不能直接把旧配置一次替换为新配置？

**答案：**

如果旧配置和新配置分别独立选举多数派，而两个多数派可能完全不相交，网络分区时就可能同时选出两个领导者。例如旧集群为 `{A,B,C}`，新集群为 `{D,E,F}`，两边各自获得多数票，不再满足任意两个法定人数必有交集的安全条件。

经典 Raft 使用联合共识。集群先提交 `C_old,new`，这一阶段日志复制和选举都需要同时获得旧配置多数派与新配置多数派；联合配置提交后，再提交只包含新成员的 `C_new`。这样过渡期间任何合法多数派都与前后配置保持必要交集。

实现时还要处理领导者被移出配置、学习者追赶、配置日志尚未提交时领导者崩溃等情况。新增节点通常先以 learner 身份同步日志，达到阈值后再进入投票配置，避免一个落后节点降低集群可用性。

10. NUMA 机器上线程池吞吐突然下降，应如何判断是否由远端内存访问造成？

**答案：**

NUMA 系统中，每个 CPU 节点访问本地内存延迟更低。内存通常按照首次触页策略分配：哪个线程首次写入页面，页面就倾向分配到该线程所在节点。如果主线程先初始化全部任务缓冲区，随后工作线程分散到其他节点，大量访问会成为远端访问。

排查时应同时查看线程 CPU 归属、页面分布、远端访问计数和内存带宽。可以使用 `numactl --hardware`、`numastat -p`、`perf mem` 以及硬件 uncore 计数器，不能只看 CPU 利用率。

优化通常是让工作线程固定到节点，并由对应线程首次初始化本地数据；任务队列和内存池按 NUMA 节点分片，尽量在本节点消费。若数据确实被所有节点均匀读取，可以考虑交错分配。盲目绑核也可能导致负载不均，因此需要在局部性和调度弹性之间取舍。

11. PostgreSQL 的 SSI 如何在不使用传统两阶段锁的情况下实现可串行化？

**答案：**

Serializable Snapshot Isolation 在快照隔离基础上跟踪读写依赖。事务读取某个版本或谓词范围后，另一个并发事务写入对应数据，会形成 rw-antidependency。系统检测依赖图中可能构成危险结构的模式，例如 `T1 ->rw T2 ->rw T3`，并中止其中一个事务，避免最终形成不可串行化环。

SSI 的读通常不会阻塞写，而是通过 SIREAD 谓词锁记录“读过什么”。这种锁不是传统排他锁，但会消耗内存，并可能随着扫描范围扩大而升级。只读事务在满足安全快照条件后可以避免继续跟踪冲突。

应用必须把序列化失败视为正常并发结果，对完整事务进行重试。重试不能只重放最后一条 SQL，并且事务内调用外部系统会使重试变得危险，通常需要 outbox 或幂等接口隔离副作用。

12. QUIC 在发生连接迁移时，为什么不能继续只使用四元组标识连接？

**答案：**

TCP 连接由源地址、源端口、目标地址和目标端口四元组标识。移动设备从 Wi-Fi 切换到蜂窝网络后，源地址和端口可能变化，如果 QUIC 也只依赖四元组，原连接就无法延续。

QUIC 使用 Connection ID 标识逻辑连接，使端点可以在网络路径变化后继续找到连接状态。客户端切换路径后，服务端会通过 PATH_CHALLENGE 和 PATH_RESPONSE 验证新地址确实可达，再将主要发送路径迁移过去。

Connection ID 也不能长期固定，否则观察者可以用它跨网络关联用户。端点可以预先发放多个 Connection ID 并在迁移时轮换。服务端集群通常在 Connection ID 中编码路由信息，但需要加密或认证，避免泄露内部拓扑以及被伪造后形成流量攻击。

13. `std::pmr` 如何降低高频小对象分配成本？资源生命周期设计错误会发生什么？

**答案：**
```
#include <array>
#include <memory_resource>
#include <string>
#include <vector>

void parseRequest() {
    std::array<std::byte, 8192> storage{};
    std::pmr::monotonic_buffer_resource arena(
        storage.data(), storage.size());

    std::pmr::vector<std::pmr::string> fields{&arena};
    fields.emplace_back("content-type");
    fields.emplace_back("application/octet-stream");
}

```

`std::pmr` 将容器的内存分配策略从类型中分离出来。大量生命周期相近的小对象可以使用 `monotonic_buffer_resource`，从大块内存中顺序切分，单次释放整个资源，避免逐对象调用通用分配器。



容器不拥有 `memory_resource`。如果容器比资源活得更久，容器中的内存地址会失效，后续访问或析构产生未定义行为。把使用栈上资源的 `pmr::vector` 返回给调用方就是典型错误。

另外，移动一个 PMR 容器时，如果目标分配器不同，操作可能退化为逐元素移动，不能简单假设移动永远是 O(1)。


## 下面的无符号整数转换函数存在哪些设计问题？如何重新实现？

```
char* UIntToStr(unsigned int value);
```
**答案：**

这个接口没有表达返回内存的所有权。调用方无法判断返回值来自 `malloc`、`new[]`、静态缓冲区还是线程局部缓冲区，也就无法确定是否需要释放以及应该使用哪种方式释放。

如果返回全局或静态缓冲区，多次调用会覆盖旧结果，多线程调用还可能产生数据竞争。让调用方传入缓冲区，则必须额外处理容量不足和字符串终止符的问题。

现代 C++ 中直接返回 `std::string` 更合适。返回值优化和移动语义可以避免不必要的复制。
```
#include <algorithm>
#include <string>

std::string UIntToString(unsigned int value) {
    if (value == 0) {
        return "0";
    }

    std::string result;

    while (value != 0) {
        result.push_back(
            static_cast<char>('0' + value % 10));
        value /= 10;
    }

    std::reverse(result.begin(), result.end());
    return result;
}

```

如果接口禁止动态分配，可以通过 `std::to_chars` 写入调用方提供的缓冲区：
```
#include <charconv>
#include <span>
#include <string_view>
#include <system_error>

std::string_view UIntToChars(
    unsigned int value,
    std::span<char> buffer) {

    auto [end, error] = std::to_chars(
        buffer.data(),
        buffer.data() + buffer.size(),
        value);

    if (error == std::errc::value_too_large) {
        return {};
    }

    return {
        buffer.data(),
        static_cast<size_t>(end - buffer.data())
    };
}

```

## 3. 实现 `memmove` 时，如何处理源内存和目标内存重叠？

**答案：**

`memcpy` 不保证重叠区域的复制结果，而 `memmove` 必须保证复制后的结果等价于先把源数据放入临时缓冲区，再写入目标区域。

目标地址位于源地址之前时，可以从低地址向高地址复制；目标地址落在源区间内部且位于源地址之后时，必须从高地址向低地址复制，否则前面写入的数据会覆盖后面尚未读取的源数据。

不能直接使用两个不相关对象的普通指针做大小比较。下面将地址转换为 `uintptr_t` 后判断方向

```
#include <cstddef>
#include <cstdint>

void* MyMemmove(void* destination,
                const void* source,
                size_t length) {
    if (destination == source || length == 0) {
        return destination;
    }

    auto* dst = static_cast<unsigned char*>(destination);
    const auto* src =
        static_cast<const unsigned char*>(source);

    const uintptr_t dstAddress =
        reinterpret_cast<uintptr_t>(dst);
    const uintptr_t srcAddress =
        reinterpret_cast<uintptr_t>(src);

    if (dstAddress < srcAddress ||
        dstAddress - srcAddress >= length) {
        for (size_t i = 0; i < length; ++i) {
            dst[i] = src[i];
        }
    } else {
        for (size_t i = length; i != 0; --i) {
            dst[i - 1] = src[i - 1];
        }
    }

    return destination;
}

```


## 4. 找出下面函数中的未定义行为和接口缺陷，并给出安全实现
```
const char* PhoneSearch(
    const unsigned int phoneNum,
    const std::map<unsigned int, std::string>& addressBook) {

    std::string tempPhone;
    memset(&tempPhone, 0, sizeof(tempPhone));

    tempPhone = addressBook[phoneNum];

    if (tempPhone.c_str() == "not exist") {
        return nullptr;
    }

    return tempPhone.c_str();
}

```
`std::string` 不是平凡字节对象，对它执行 `memset` 会破坏内部状态，后续赋值和析构都属于未定义行为。

`addressBook` 是 `const`，不能调用可能插入元素的 `operator[]`，这段代码无法通过正常的类型检查。即使去掉 `const`，查询不存在的键也会插入空字符串，不符合纯查询语义。

`tempPhone.c_str() == "not exist"` 比较的是两个指针地址，不是字符串内容。最严重的问题是函数返回局部字符串内部缓冲区的地址，函数结束后 `tempPhone` 被析构，返回值立即悬空。

可以使用 `std::optional<std::reference_wrapper<const std::string>>`，既不复制字符串，也能明确表达未找到：
```cpp
#include <functional>
#include <map>
#include <optional>
#include <string>

using SearchResult =
    std::optional<std::reference_wrapper<const std::string>>;

SearchResult PhoneSearch(
    unsigned int phoneNum,
    const std::map<unsigned int, std::string>& addressBook) {

    auto it = addressBook.find(phoneNum);
    if (it == addressBook.end()) {
        return std::nullopt;
    }

    return std::cref(it->second);
}

```
调用方取得的引用只在对应元素未被删除且 `addressBook` 仍然存活时有效。如果无法保证容器生命周期，应该返回 `std::optional<std::string>`。

5. 多个线程不断写入同一个 unsigned int，另一个线程读取时可能看到哪些值？
```
unsigned int value = 0;
 
void writer1() {
    while (true) {
        value = 0x11111111;
    }
}
 
void writer2() {
    while (true) {
        value = 0x22222222;
    }
}
```
答案：

从 C++ 语言层面看，不能回答“只会看到哪几个值”。多个线程对普通变量并发写入，且不存在 happens-before 关系，已经构成数据竞争，整个程序具有未定义行为。

即使某个平台能保证对齐的 32 位写入在硬件上不可撕裂，编译器仍然可以基于“合法程序不存在数据竞争”的前提进行优化。例如读取线程可能只读取一次，也可能把某些分支删除。

volatile 不能解决线程同步问题，它主要用于描述某些不能被普通优化规则处理的访问，并不建立线程间顺序。

只要求读取某一次完整写入的结果，可以使用 relaxed 原子操作：
```
std::atomic<unsigned int> value{0};
 
void writer1() {
    while (true) {
        value.store(0x11111111,
                    std::memory_order_relaxed);
    }
}
 
void writer2() {
    while (true) {
        value.store(0x22222222,
                    std::memory_order_relaxed);
    }
}
 
unsigned int readValue() {
    return value.load(std::memory_order_relaxed);
}
```
此时读取值来自原子对象的某次修改，但不同线程仍然无法仅凭读取结果确定全局时间顺序。

6. compare_exchange_weak 为什么允许无原因失败？循环中应如何正确使用？
答案：

compare_exchange_weak 即使原子对象当前值等于期望值，也允许返回失败，这称为伪失败。某些使用 load-linked/store-conditional 实现原子操作的体系结构中，只要缓存行受到干扰，条件存储就可能失败，weak 版本允许直接将这种失败暴露给调用方。

CAS 失败后，expected 会被改写成原子对象的当前值，因此一般不需要每次手动重新加载。

```
#include <atomic>
#include <cstdint>
 
void atomicMax(std::atomic<uint64_t>& target,
               uint64_t candidate) {
    uint64_t current =
        target.load(std::memory_order_relaxed);
 
    while (current < candidate &&
           !target.compare_exchange_weak(
               current,
               candidate,
               std::memory_order_relaxed,
               std::memory_order_relaxed)) {
    }
}
```
成功和失败内存序不能随意填写。失败路径只发生读取，不能使用 release 或 acq_rel。此外，CAS 循环只解决原子更新，不自动解决 ABA 和对象回收问题。

7. std::string_view 在什么情况下会变成悬空引用？
答案：

std::string_view 只保存字符指针和长度，不拥有底层字符。原字符串析构、重新分配或被修改后，原有视图可能失效。

返回临时字符串对应的 string_view 会立即悬空：
```

    std::string name = "backend";
    return name; // 错误
}
```
即使原字符串仍然存在，扩容也可能使视图失效：

```
std::string text = "abc";
std::string_view view = text;
 
text += std::string(1024, 'x');
```
// text 可能重新分配，view 可能已经悬空
解析器可以在输入缓冲区生命周期明确时使用 string_view 做零拷贝切片。若结果需要跨异步任务、跨线程队列或长期保存，应复制为 std::string，或者让视图与共享的底层缓冲区一起传递。

8. std::vector 扩容时，为什么有时复制元素而不是移动元素？
答案：

扩容需要在新内存中构造元素。如果逐个移动时某个元素的移动构造函数抛出异常，旧元素可能已有一部分被修改，容器难以恢复到扩容前的状态。

为了尽可能提供强异常保证，当类型的移动构造函数可能抛异常、但复制构造函数可用时，vector 通常选择复制。只有移动构造函数是 noexcept，或者类型不可复制时，才倾向于移动。
```
class Buffer {
public:
    Buffer(Buffer&& other) noexcept
        : data_(std::exchange(other.data_, nullptr)),
          size_(std::exchange(other.size_, 0)) {}
 
    Buffer& operator=(Buffer&& other) noexcept {
        if (this != &other) {
            delete[] data_;
            data_ = std::exchange(other.data_, nullptr);
            size_ = std::exchange(other.size_, 0);
        }
        return *this;
    }
 
    ~Buffer() {
        delete[] data_;
    }
 
private:
    char* data_ = nullptr;
    size_t size_ = 0;
};
```
移动操作能够保证不抛异常时，应明确标记 noexcept，否则标准容器可能无法采用预期的移动优化。

9. 一个拥有 const、引用和原子成员的类型，编译器会生成哪些特殊成员函数？
答案：

编译器是否生成复制赋值和移动赋值，取决于每个成员能否执行对应操作。

引用成员不能被重新绑定，因此包含引用成员的类型，其默认复制赋值和移动赋值通常会被删除。const 数据成员不能被赋值，也会导致默认赋值运算符被删除。`std::atomic<T> `不提供普通复制构造和复制赋值，因此包含原子成员的类型也不会自动成为可复制类型。

```
#include <atomic>
 
struct State {
    const int id;
    int& external;
    std::atomic<int> status;
 
    State(int idValue, int& ref)
        : id(idValue), external(ref), status(0) {}
 
    State(const State&) = delete;
    State& operator=(const State&) = delete;
    State(State&&) = delete;
    State& operator=(State&&) = delete;
};
```
如果业务确实需要复制，必须定义复制的语义。例如原子成员可以通过 load 初始化，但引用成员复制后究竟继续引用原对象，还是引用另一个对象，需要由接口明确决定，不能机械地补一个复制函数。

10. 为什么在信号处理函数中调用 printf、malloc 或获取互斥锁可能死锁？
答案：

信号可能在程序执行任意用户态指令时到达。如果当前线程正在执行 malloc 并持有分配器内部锁，信号处理函数再次调用 malloc，就会等待同一个线程释放锁，形成不可恢复的重入死锁。

printf 可能获取 stdio 锁并申请内存，C++ 流、日志库、智能指针析构和大部分标准容器同样不满足异步信号安全要求。普通互斥锁也不能在信号处理函数中安全使用。

信号处理函数通常只执行最小操作，例如设置 volatile sig_atomic_t 标记，或者向 self-pipe、eventfd 写入一个值，再由正常事件循环处理。

## 1. 什么是内联函数（inline）？

- **定义**：用 inline 关键字修饰的函数，建议编译器在调用处展开函数体，而不是进行常规的函数调用
- **优点**：消除函数调用开销（压栈、跳转、返回），提高执行效率，特别适合小型、频繁调用的函数
- **缺点**：代码膨胀，如果函数体较大或调用次数多，会增加可执行文件大小
- **注意事项**：inline 只是建议，编译器可能忽略；递归函数、虚函数通常不会内联；类内定义的成员函数默认是 inline
- **使用场景**：getter/setter、简单的数学运算、循环内的小函数

## 2. 如何定义和使用常量表达式（constexpr）？

- **定义**：C++11 引入，表示值可以在编译期计算的常量表达式
- **constexpr 变量**：`constexpr int SIZE = 100;` 必须用常量表达式初始化，可用于数组大小等需要编译期常量的地方
- **constexpr 函数**：`constexpr int square(int x) { return x * x; }` 如果参数是常量，编译期求值；否则运行期执行
- **与 const 区别**：const 只保证不可修改，constexpr 保证编译期可求值。constexpr 隐含 const
- **C++14 增强**：constexpr 函数可以包含多条语句、局部变量、循环等
- **使用场景**：性能优化、模板元编程、编译期计算
## 3. C++ 中的虚函数是什么？

- **定义**：用 virtual 关键字修饰的成员函数，支持动态绑定
- **作用**：允许派生类重写（override）基类函数，通过基类指针/引用调用时执行派生类版本
- **语法**：`virtual void func();` 派生类重写时 virtual 可省略，但建议加 override 关键字
- **虚函数表**：编译器为每个有虚函数的类生成 vtable，存储虚函数地址。对象的 vptr 指向对应的 vtable
- **构造/析构中的虚函数**：构造函数不能是虚函数；析构函数应该是虚函数；构造/析构过程中调用虚函数不会动态绑定
- **性能**：虚函数调用比普通函数多一次间接寻址，通常影响很小
- **final 关键字**：C++11 可用 final 防止虚函数被进一步重写

## 4. C++ 中的纯虚函数（Pure Virtual Function）是什么？

- **定义**：在基类中声明但不实现的虚函数，语法：`virtual void func() = 0;`
- **作用**：定义接口规范，强制派生类必须实现该函数
- **抽象类**：包含纯虚函数的类是抽象类，不能实例化
- **派生类要求**：派生类必须实现所有纯虚函数才能实例化，否则仍是抽象类
- **可以有实现**：纯虚函数可以提供默认实现，派生类可以显式调用
- **使用场景**：定义接口、框架设计、多态基类
- **示例**：`class Shape { virtual double area() = 0; };`

## 8. C++ 中如何实现运算符重载？

- **语法**：`返回类型 operator符号(参数列表)`，如 `Complex operator+(const Complex& other)`
- **成员函数形式**：左操作数是this，`c1 + c2` 调用 `c1.operator+(c2)`
- **友元函数形式**：两个操作数都是参数，`c1 + c2` 调用 `operator+(c1, c2)`，支持左操作数类型转换
- **不能重载的运算符**：`::`、`.`、`.*`、`?:`、`sizeof`、`typeid`
- **必须是成员函数**：`=`、`[]`、`()`、`->`
- **常见重载**：算术运算符、比较运算符、流运算符（`<<`、`>>`）、下标运算符、函数调用运算符
- **返回值**：算术运算符返回值，赋值运算符返回引用支持链式调用
- **最佳实践**：保持运算符的直观语义，不要滥用

## 9. C++ 中如何使用友元函数（Friend Function）？

- **定义**：在类中用 friend 声明的非成员函数，可以访问类的 private 和 protected 成员
- **声明**：`class MyClass { friend void func(MyClass& obj); };`
- **特点**：不是成员函数，没有 this 指针；破坏封装性，但有时必要
- **使用场景**：①运算符重载（如 `<<`、`>>` 需要左操作数是流对象）②需要访问多个类的私有成员 ③提高效率避免 getter/setter
- **友元类**：`friend class OtherClass;` 允许另一个类访问私有成员
- **单向性**：A 是 B 的友元，B 不自动是 A 的友元
- **不传递**：A 是 B 的友元，B 是 C 的友元，A 不是 C 的友元
- **不继承**：基类的友元不是派生类的友元
- **最佳实践**：尽量少用，优先考虑 public 接口

## 5. C++ 中如何管理内存？

**1. 栈内存管理：** 局部变量自动分配在栈上，作用域结束自动释放，速度快但空间有限（通常 1-8MB），适合小对象和临时变量，栈溢出会导致程序崩溃。

**2. 堆内存管理：** 使用 new/delete 或 malloc/free 手动管理，空间大但速度慢，容易泄漏和碎片化，现代 C++推荐用智能指针代替手动管理，避免直接使用 new/delete。

**3. 静态/全局内存：** 程序启动时分配程序结束时释放，生命周期贯穿整个程序，适合全局配置和单例对象，过度使用会增加内存占用和启动时间。

**4. 现代 C++最佳实践：** 优先使用栈内存和 RAII，使用智能指针管理堆内存，使用 STL 容器代替手动数组，避免裸指针和手动内存管理，使用内存池优化频繁分配，定期使用工具检测泄漏和越界。

## 10. 如何优化 C++ 中的内存访问模式？

**1. 缓存友好访问：** 按顺序访问连续内存利用 CPU 缓存，避免随机访问和指针跳转，使用数组代替链表提高缓存命中率，结构体成员按访问频率排列热数据放一起。

**2. 数据局部性：** 时间局部性（短时间内重复访问同一数据），空间局部性（访问相邻地址的数据），使用 SoA（Structure of Arrays）代替 AoS（Array of Structures）提高向量化效率。

**3. 避免 false sharing：** 多线程访问不同变量但在同一缓存行会导致缓存失效，使用 alignas(64)对齐到缓存行，使用 thread_local 避免共享，在结构体中添加 padding 分隔热数据。

**4. 预取和预分配：** 使用__builtin_prefetch 预取数据到缓存，使用 reserve 预分配容器空间避免重新分配，批量处理数据提高缓存利用率，使用内存池保持内存连续性。


## 1. C++ 中的线程（std::thread）如何创建和管理？

**1. 创建线程：** 使用 std::thread 构造函数传入可调用对象（函数、lambda、函数对象），线程创建后立即开始执行，可以传递参数给线程函数，参数默认按值拷贝可以用 std::ref 传引用。

**2. 线程管理：** 必须调用 join()等待线程结束或 detach()分离线程，未 join 或 detach 的线程析构时会调用 std::terminate，joinable()检查线程是否可 join，get_id()获取线程 ID，hardware_concurrency()获取硬件并发数。

**3. 参数传递：** 参数按值拷贝到线程内部避免悬空引用，使用 std::ref 传递引用，使用 std::move 转移所有权，注意线程函数的参数生命周期必须长于线程执行时间。

**4. 注意事项：** 线程不可拷贝只能移动，异常安全需要确保 join 或 detach 被调用，避免在析构函数中启动线程，使用 RAII 封装线程管理（如 jthread C++20）。

## 2. C++ 中的 std::mutex 和 std::lock_guard 是如何工作的？

**1. std::mutex 工作原理：** 互斥锁提供独占访问保护临界区，lock()获取锁（阻塞直到成功），unlock()释放锁，try_lock()尝试获取锁立即返回，同一线程重复 lock 会死锁。

**2. std::lock_guard 特点：** RAII 封装的锁管理器，构造时自动加锁析构时自动解锁，不可拷贝不可移动，适合简单的作用域锁定，无法手动 unlock 只能等待析构。

**3. std::unique_lock 特点：** 更灵活的锁管理器，可以手动 lock/unlock，支持延迟加锁和条件变量，可以移动但不可拷贝，可以提前释放锁或转移所有权。

**4. 使用建议：** 优先使用 lock_guard 简单高效，需要灵活控制时使用 unique_lock，锁的粒度尽可能小减少竞争，避免在持有锁时调用外部函数防止死锁。

## 3. C++ 中如何使用 std::condition_variable 进行线程同步？

**1. 基本概念：** 条件变量用于线程间的通知机制，一个线程等待条件满足另一个线程通知条件改变，必须配合 mutex 和 unique_lock 使用，避免虚假唤醒需要在循环中检查条件。

**2. 主要操作：** wait()释放锁并等待通知，被唤醒后重新获取锁，notify_one()唤醒一个等待线程，notify_all()唤醒所有等待线程，wait_for()和 wait_until()支持超时等待。

**3. 虚假唤醒：** 线程可能在没有 notify 的情况下被唤醒，必须使用 while 循环检查条件而不是 if，wait()的第二个参数可以传入谓词自动处理虚假唤醒。

**4. 使用模式：** 生产者通知消费者数据就绪，任务队列的等待和通知，线程池的任务分发，实现信号量和屏障等同步原语。

## 5. C++ 中如何避免死锁？

**1. 死锁条件：** 互斥（资源独占）、持有并等待（持有资源同时等待其他资源）、不可抢占（资源不能被强制释放）、循环等待（线程间形成环形等待链），四个条件同时满足才会死锁。

**2. 避免策略：** 按固定顺序获取锁避免循环等待，使用 std::lock 同时获取多个锁，使用 try_lock 尝试获取失败则释放已持有的锁，设置超时机制避免无限等待。

**3. 锁的层次：** 为锁分配优先级总是按优先级顺序获取，使用 lock_guard 和 unique_lock 的 RAII 特性自动释放，避免在持有锁时调用外部函数或回调，减小锁的粒度和持有时间。

**4. 检测和恢复：** 使用死锁检测工具（ThreadSanitizer），设计时避免嵌套锁，使用无锁数据结构，实在需要多个锁时使用 std::scoped_lock（C++17）一次性获取所有锁。

## 2. C++ 中的 std::move 和 std::forward 有什么区别？

**1. std::move 作用：** 无条件将左值转换为右值引用，不移动任何东西只是类型转换，告诉编译器可以移动这个对象，实际移动由移动构造/赋值完成，使用后源对象不应再使用。

**2. std::forward 作用：** 完美转发保持参数的值类别，左值转发为左值右值转发为右值，用于模板函数转发参数，避免不必要的拷贝，实现泛型代码的高效转发。

**3. 使用场景：** move 用于明确表示转移所有权，forward 用于模板函数的参数转发，move 是无条件转换 forward 是有条件转换，move 用于实现移动语义 forward 用于实现完美转发。

**4. 实现原理：** move等价于static_cast<T&&>，forward 根据模板参数决定转换类型，都是编译期操作无运行时开销，正确使用可以显著提高性能。

### 1. QString 和 std::string 有什么区别？

**QString** 和 **std::string** 都是用于存储字符串的类，但它们之间有一些显著的区别：

1. 字符编码：QString：采用 UTF-16 编码，支持多语言字符集和 Unicode 字符，适用于国际化应用。std::string：使用 ASCII 或 UTF-8 编码，适用于较为简单的字符串操作，通常在英文或单语言环境中使用。
2. 内存管理：QString：使用隐式共享（Implicit Sharing）机制，多个 QString 对象可以共享同一内存区域，提高内存利用率。修改时会创建新的副本，避免对其他共享的字符串造成影响。std::string：标准 C++ 类，采用直接管理内存，即每个 std::string 对象有自己的内存，不使用隐式共享。
3. API：QString：提供了大量的成员函数，支持 Unicode 字符串的处理、字符串操作和格式化。std::string：提供了标准的 C++ 字符串操作，更多与 C 风格字符串兼容，通常与 const char* 一起使用。
4. 性能：QString：在处理 Unicode 字符时具有更高的灵活性，但在某些情况下性能开销较大。std::string：通常性能较好，尤其是在单字节字符的情况下，但不直接支持多语言字符。

QtConcurrent：这是 Qt 提供的并行编程框架，通过较为简单的接口（如 QtConcurrent::run()）来并行执行函数。
QThreadPool：管理一组线程，允许将任务提交给线程池，而不需要手动创建和管理线程。适用于任务较为简单且数量较多的情况。

2. QThread 的使用方法是什么？
QThread 是 Qt 用来创建和管理线程的类，通常的使用步骤如下：

继承 QThread 并重写 run()：在 run() 方法中编写需要在线程中执行的代码。
启动线程：通过调用 start() 启动线程，start() 会自动调用 run() 方法。
### 3. 继承 QThread 和使用 moveToThread()有什么区别？

这两种方式实现多线程的机制各有特点：

1. 继承 QThread：直接继承 QThread 类并重写 run() 方法来实现线程的执行逻辑。在 run() 方法中执行耗时任务或循环。适合在新线程中执行一些独立的工作逻辑。缺点：当线程与 QObject 结合时（如 GUI 线程中的工作对象），不建议直接继承 QThread。因为 QObject 不允许在多个线程中同时访问。
2. 使用 moveToThread()：将一个 QObject 派生的对象移到一个新的线程中，这样该对象的槽函数就可以在该线程中执行。适用于需要将某个对象放入工作线程，但不需要继承 QThread。优点：可以避免 QObject 在多个线程中共享的问题，线程管理更灵活。缺点：需要手动管理线程的启动、停止和对象的销毁。

### **4. 线程和进程的本质区别是什么？它们如何进行通信？**

**答案要点：**

2. **地址空间**：进程拥有独立地址空间，线程共享进程的地址空间和资源

**答案要点：**

2. **条件变量(condition_variable)**：线程间的通知机制，配合 mutex 使用，避免忙等待
3. **读写锁(shared_mutex)**：允许多个读线程同时访问，写操作独占
4. **原子操作(atomic)**：无锁编程，适用于简单的计数器、标志位等场景

**答案要点：**

### **3. 说说 TCP 和 UDP 的区别，什么场景下用 UDP？**

**答案要点：**

1. **连接性**：TCP 面向连接（三次握手），UDP 无连接，开销更小
2. **可靠性**：TCP 保证数据顺序和完整性（重传、确认），UDP 不保证，可能丢包乱序
3. **性能**：UDP 延迟低、吞吐量高，适合实时性要求高的场景
4. **应用场景**：UDP 用于视频直播、在线游戏、DNS 查询、IoT 设备通信等

### **4. 解释一下 TCP 的拥塞控制机制**

**答案要点：**

1. **慢启动**：连接建立初期，拥塞窗口指数增长，快速探测网络容量
2. **拥塞避免**：达到阈值后线性增长，避免网络过载
3. **快速重传**：收到 3 个重复 ACK 立即重传，不等超时
4. **快速恢复**：重传后将阈值设为当前窗口一半，进入拥塞避免阶段

2. **AddressSanitizer**：编译时加-fsanitize=address，运行时检测内存错误，性能损耗小
3. **代码审查**：检查 new/delete、malloc/free 配对，智能指针使用是否正确
4. **日志分析**：记录内存分配释放，分析内存增长趋势，定位泄漏点

### **6. 什么是 RAII？它解决了什么问题？**

**答案要点：**

1. **资源获取即初始化**：在构造函数中获取资源，析构函数中释放资源，利用对象生命周期管理资源
2. **异常安全**：即使发生异常，栈展开时也会调用析构函数，保证资源释放
3. **典型应用**：智能指针、lock_guard、unique_lock、文件句柄封装
4. **优势**：避免手动管理资源，减少内存泄漏和资源泄漏风险
