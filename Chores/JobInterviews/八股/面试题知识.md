### Name Mangling
#### 基本原理
C 语言中函数名全局唯一，编译器直接使用原名.
C++ 编译器为了支持函数重载、命名空间、类成员，模板等特性，在编译过程中根据这些信息将函数名、变量名等符号转换为一个唯一内部标识符的机制
不同编译器（如 GCC 与 MSVC）的修饰规则不同，导致 C++ 二进制库不易跨编译器混用。
调试或逆向分析时可通过 c++filt 等工具将修饰名还原为可读形式。
#### 关闭方法
使用 `extern "C"` 告诉编译器“禁用 Name Mangling”，但在实际开发编写跨语言调用的动态库 DLL/SO 时，如果想要重新编译大量文件的情况下更改符号名，可以使用:
- GCC / Clang 的 `asm` 标签 (Label)，在符号后添加 `__asm__("symbol_name")` 指定 mangling 名称
- MSVC 的 `.def` 模块定义文件，在链接时提供一个 `.def` 文件，强制映射导出名
```text
; my_library.def
EXPORTS
    my_clean_api_name = ?Bar@Foo@@QAEXXZ  ; 将 C++ 的 mangled name 映射为纯 C 名字
```
源码里依然是 C++ 的 Mangling 名字，但链接器在生成 DLL 时，对外暴露的符号被强制改成了指定内容
