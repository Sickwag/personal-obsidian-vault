# 上海瀛宇通信--软件开发工程师

## 面试复盘（人事面 · 2026-08）

> 性质判定：这是一场**人事面**（HR 面），不是技术面。全程 HR 在做「性格 / 动机 / 学习力 / 表达能力 / 稳定性 / 团队协作」考察，没有技术追问和算法题。你以为是技术面，所以把项目设计细节讲给了人事听。

---

| 维度     | 评价                                                                                                                         |

---

### 二、暴露出的问题（按严重度排序）

#### 1. 没区分 HR 面 / 技术面，把技术细节砸向人事 —— ⭐ 最高频
- **表现**：项目介绍全篇「Ragel 状态机 / dlsym / 前缀树 / 两级路由」砸给一个 HR。人事要的不是技术深度，是「你能不能讲清、有没有热情、逻辑清不清楚」。
- **改法**：拿不准对方水平时，**先给 30 秒「人话总结」，再确认「您想听工程设计，还是底层实现细节？」**。对 HR 版本，说「我手工从零写了一个网络库/后端框架，相当于自己造了轮子，不想直接调成熟框架」——外行能懂，又显出钻研劲。

#### 2. 自我评价过度自贬，直接打脸「极客人设」 —— ⭐ 最关键
- **表现**：被问「你能力到什么阶段」，连说「我连 Redis 和 MySQL 都不会反推架构」「从 0 到 1 做不到」「欠缺火候」。
- **危害**：这家公司恰恰最看重「自己钻研、自己琢磨、喜欢开发」。你亲手把第一印象从「极客」拉成「不自信的应届生」。
- **改法**：能力问题给**结构化回答**，不给自我批评：
  1. 「我能独立做从 0 到 1 的完整闭环——林草惠农 APP 是我大学独立上架的」；
  2. 「我也擅长在已有系统上做深度优化——实习里用火焰图定位热点、改代码」；
  3. 「从 0 到 1 设计大型架构这步我还在成长，但我学习路径可验证（笔记 500 天 + 多个实战项目）」。
  短板**说一句带一句「我在补」就行，别再反复强调**。

#### 3. 必考题「你的优势」没准备，先反问 —— 暴露没做准备
- **表现**：HR 问「你来这个岗位有什么优势」，你反问「技术方面的还是什么方面的？」逼 HR 补救。
- **实在**：「你为什么适合这个岗位」是 100% 必考，**必须提前刻好一个能套用的「3 点优势」模板**（技术+学习力+协作，三条各带一个例）。反问显被动。

#### 4. 「心态故事」讲出了风险信息 —— 篇幅太长
- **表现**：花一大段讲「我以前看不起周围同学，后来反思是自己『严于待人、宽于待己』，现在变亲和了」。
- **风险**：HR 听到的首先是「这个人曾经傲慢、轻视同学」，成长叙事救不回第一印象。
- **改法**：**压缩成一句**：「这几年最大的成长，是把心态从『锋芒』调成『协作』，更能吸收别人优点、一起成事。」重点放在「现在我能合作」——HR 极其看重团队协作。

#### 5. 数字 / 术语表述不准、时间线绕
- **英语**：说成「16 级」，应为 **CET-6**（六级）。这是必会被追问的基础项，念准。
- **项目名**：「IEEE1722Tp」两次说成「IEE1712TP」。项目名必须念准。
- **竞赛级别**：ACM 是**省赛**；蓝桥杯三等奖**仅赛区/东北赛区**，不是全国。级别表述要自洽，别让面试官追问出「原来只是省赛」的落差。

#### 6. 把主动调研说成「猜 / 可能」，自减信用分
- **表现**：连说两次「我猜公司可能是做上位机」。
- **改法**：把「猜」换成「我做了验证」：「我看了贵公司官网，判断这个岗位偏上位机，昨天专门搭了一个工作流把 C#/WPF 的上位机开发流程跑了一遍。」——主动跟学历绑定，才有说服力。

### 三、讲述不清楚 / 可优化点

- **长段无结构**：多处一答几百字、「主谓宾」绕圈，填充词（然后/就是/所以说）密集。改法：养成「**结论先行 + 三个要点**」，练 30 秒能说完的版本。
- **AI 那个大段**「软件工程只剩头尾、中间被 AI 替代」讲得最有内容但太长，HR 听到一半就跑了。压缩成「AI 代替重复编码，人上移到架构设计与审查」一句 + 一个例子。
- **实习收获段反复解释同一件事**（个人提交 vs 团队流程差很大），讲了两遍。一个点讲一次、讲透即可。

### 四、整体评价 + 亮点（要保留）

**亮点**
1. 项目开局结构清晰（看得出练过 5 分钟版），是全场最顺的一段。
2. 「笔记 500+ 天连续更新」是强证据，且和「查自己笔记不重新搜网」绑定了实际收益。
3. 「林草惠农」讲出了「从 0 到 1 独立闭环 + 跨领域协作(找学姐设计UI) + 上架」，是极客人设的最佳注脚。
4. 主动查公司官网、反向问「公司招这个岗位的想法」——收尾很好。
5. 全程真诚、不装，愿意转 C#/WPF，契合公司「不挑语言」的招人模式。

**整体结论**
- 技术底子和学习力**够**，是「能自学、有成果、爱钻研」的苗子。
- 但这场 HR 面在「极客人设」上打软了：自我否定 + 长篇冗长 + 细节砸错对象 + 必考题没准备。
- **对这家公司，最该补的不是技术，是「卖相」**：把一个结构化的「优势 3 点」练熟，把能力评价从「我做不到」翻成「我从 0 到 1 做过、也擅长优化」，把心态故事压缩成一句。

---

### 五、对该公司后续技术面的准备建议

- 瀛宇非内推、不限语言、看作品集 + 表达能力。技术面大概率 = **深挖项目 + 一个编码/设计小任务 + 看你学新东西的 demo**。
- **强烈建议**：用你搭的工作流，在技术面前**亲手产出一个 C#/WPF 的上位机 demo**（哪怕是最简单的「串口读取一次 + 一个仪表控件 UI」）。既证明爱钻研、又证明快速上手，正好对准公司「一边学一边做 demo」的培训模式，是这家公司的差异化加分项。
- 把「协程框架 / ERP / IM」三个项目各备一个**「一段话讲给非技术人事听」的版本**（人话版，不堆术语），防止下次又被安排成先跟人事聊。
